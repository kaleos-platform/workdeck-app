# UI 시각 계획

글 대신 그림으로 계획하고, 승인된 뒤에 구현한다. 정본은 코드와 `DESIGN.md`(저장소 루트)이고 와이어프레임은 구조 합의용이다.

## 언제 쓰나 (2026-11-16 규칙)

- **반드시:** 새 화면·새 route / 화면 흐름·단계·진입점·메뉴 구조 변경 / 정보 구조 변경(무엇을 어느 화면·탭·섹션에 둘지) / 상호작용 방식 변경(폼↔마법사, 표↔카드, 모달↔페이지, 일괄 작업 방식) / 모바일 배치 재구성 / 여러 화면에 걸친 같은 패턴 변경.
- **쓰지 않음:** 같은 영역 안 요소 이동·순서, 간격·색·글꼴·문구, 기존 패턴에 열·필드·버튼 하나 추가, 레이아웃 버그 수정 → `workdeck-ui` 라이브 작업대에서 바로.
- 애매하면 에디에게 "미리보기 할까요?" 한 줄로 묻는다.

## 절차

1. 현재 화면을 캡처하고 대상 route와 컴포넌트를 읽는다.
2. `docs/design/plans/<task>/`에 아래를 만든다. `<task>`와 화면 이름은 영문 소문자·숫자·하이픈만 쓴다.
   - `flow.excalidraw`: 화면 흐름. 화면이 하나면 생략한다.
   - `<screen>.excalidraw`: 화면별 와이어프레임.
   - `plan.md`: 번호별 변경 이유. 번호당 한 줄.
3. 라이브 작업대를 띄우고 `/dev/plan/<task>`를 ego 브라우저로 캡처해 겹침·잘림을 고친다.
4. 미리보기를 보내기 전에 와이어프레임을 `git add`해 둔다(새 파일은 untracked면 `git diff`에 안 나와 에디의 캔버스 수정을 놓친다).
5. **미리보기가 기본이다.** 화면별 캡처 PNG 경로와 라이브 주소(`/dev/plan/<task>`)를 에디에게 보내고, 번호별로 고를 것만 짧게 묻는다. 캔버스에서 직접 고치는 것은 선택이다(지금까지 대부분 대화로 승인했다).
6. 에디가 캔버스를 고쳐 저장했을 때만 `git diff`(스테이지 대비 작업 트리)로 바뀐 요소를 읽어 요약한다(전체 파일을 다시 읽지 않는다). 의도가 불명확하면 추측하지 않고 묻는다.
7. 에디가 승인하면 구현한다. 승인 뒤 바뀐 결정은 `plan.md`에 적는다. 끝나면 실제 화면과 와이어프레임을 나란히 보여 주고, 구조가 확정되면 `DESIGN.md` §8 결정 기록에 한 줄(고른 안 / 버린 안: 이유)을 남긴다.

## 토큰 상한

- 화면당 요소 40개 안쪽. 바뀌는 곳만 자세히, 나머지는 큰 박스 하나로.
- 안은 최대 2개(현재안 포함 3장). 더 필요하면 먼저 묻는다.
- skeleton 형식으로 쓴다(정식 형식 변환은 화면이 한다).

## 와이어프레임 규칙

- 회색조만 쓴다. 색은 위험·주의 표시가 꼭 필요할 때만 쓴다.
- 실제 라벨과 현실적인 데이터 예시를 쓴다. `Lorem`, `제목` 같은 자리표시자는 금지한다.
- 박스에 `src/components/ui` 컴포넌트 이름을 적는다.
- 바뀌는 곳에 ①②③ 번호를 달고 `plan.md`와 맞춘다.
- 픽셀 디자인을 하지 않는다. 구조, 순서, 밀도만 정한다.
- 실고객 데이터를 쓰지 않는다.

## 파일 형식

요소는 skeleton으로 쓰면 된다. 첫 로드 때 정식 형식으로 변환된다.

```json
{
  "type": "excalidraw",
  "version": 2,
  "source": "agent",
  "elements": [
    {
      "type": "rectangle",
      "id": "filter",
      "x": 24,
      "y": 70,
      "width": 852,
      "height": 48,
      "backgroundColor": "#f3f4f6",
      "fillStyle": "solid",
      "label": { "text": "① 필터 — Select" }
    },
    { "type": "text", "id": "title", "x": 24, "y": 20, "text": "재고 현황", "fontSize": 24 }
  ],
  "appState": { "viewBackgroundColor": "#ffffff" },
  "files": {}
}
```

데스크톱은 폭 900, 모바일은 폭 390 사각형을 바깥 틀로 그린다.

## 라이브 작업대
