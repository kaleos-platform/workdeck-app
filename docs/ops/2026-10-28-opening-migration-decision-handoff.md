## 사전 이전 방식의 권장안 — 아직 전체 고객 실행 승인 아님

1. 현재 유료/잔여 권리 고객과 고객별 연결 계정·데이터 범위·파일 용량을 읽기 전용으로 재집계한다.
2. 고객별 준비 상태로 최초 복사한다. 고객 소속과 이용 권리가 확정되기 전 노출·발행·접수·청구를 시작하지 않는다.
3. 전환 전에는 원본을 수정 기준으로 유지한다. 대기 기간이 길면 일 단위 변경분 점검을 검토하되 생성/수정/삭제와 자식 본문·파일까지 확인한다.
4. 전환 시각을 고정하고 원본 쓰기 통제 → 최종 변경분 반영 → 관계/파일/공개 링크/권한 검증 → 고객 이용 시작 순서로 진행한다.
5. 고객이 Workdeck 사용을 시작하면 해당 고객에 대한 원본 자동 덮어쓰기를 중단한다. 충돌은 수동 판단한다.

현재 도구는 sourceRef·sourceHash·targetHash로 재사용/중복/충돌을 검사하지만 원본 또는 고객 수정이 달라지면 중단한다. 반복 실행이 자동 증분 동기화는 아니다. 전 고객용 배치·변경/삭제 처리·계정 준비/활성화·운영 상태 관리는 추가 설계/구현이 필요하다. 준비 상태로 숨기는 기능이 이미 존재한다고 가정하지 않는다.

24개월 정책은 고객별 snapshot T와 한국 날짜 기준 C를 고정한다. 공고/지원서 외에도 활성 템플릿·기준정보·최근 지원서의 부모·현재 접수 중 공고 등 관계 예외가 있다. 상세 정책을 참조한다. 기존 대표 고객의 명시 제외/의도적 삭제 예외는 해당 고객에만 적용하고 다른 고객에게 일괄 적용하지 않는다.
