## 5. 확인된 구현상의 함정 — 반드시 검토 문서와 코드 대조

1. **PII 복사**: 기존 posting importer는 managerName/managerPhone을 저장하고 전체 packet을 암호화 원장에 넣는다. 신규 정책용 허용 필드/변환 버전과 깨끗한 원장 입력이 필요하다. 단순 24→12 상수 교체로 실행하지 않는다.
2. **GRACE**: 현재 유예는 deck `paidActivatedAt + 14일`. `unexempt`는 flag만 바꾸므로 해제일부터 14일을 새로 주지 않는다. 즉시 잠김 또는 주기 없는 ACTIVE 무료 접근을 피해야 한다.
3. **할인 최초 결제**: `startSubscription`은 정가로 청구하고 기존 priceSnapshot도 정가로 덮어쓴다. 운영 스크립트로 할인 구독을 심는 것만으로 월 13,500원을 보장하지 못한다. 최초 청구/갱신/해지 예약 취소/실제 해지 후 재가입을 구분한다.
4. **면제 범위**: SpaceSubscription.exemptFlag는 다른 deck 접근과 Space 전체 정기청구에도 영향. 기존 다른 유료 deck 고객은 자동 면제하지 말고 예외 처리/모집 관리 한정 방식 검토.
5. **고객 다운로드**: Opening의 기존 Excel은 기본값/추가 질문 위주이며 첨부 PDF/이력서 원본·전체 이력을 함께 내보내지 않는다. 실제 보관 가능한 범위와 첨부 직접 다운로드 절차/마감을 안내해야 한다.
6. **StepPay 중단**: 참조 코드의 CancelSubscription은 `END_OF_PERIOD`를 호출하고 구독 상태를 다시 읽는다. 신규 결제 버튼 차단만으로 제공자 갱신·실패 재시도 중단을 보증하지 않는다. 운영 구독 상태·웹훅·잔여 권리를 대조한다.
7. **링크/종료**: 서버/DB 종료 후에도 동작할 구 지원 URL 매핑은 기존 DB에 의존하지 않아야 한다. 비신청/마감 고객을 다른 고객에게 잘못 연결하지 않는다. 기존 importer는 DRAFT·알림 false로 생성하며 자동 재발행하지 않는다.
8. **백업 키**: Workdeck k1 사본은 Opening 복호화키가 아니다. Opening dump의 암호화 해제키·애플리케이션 복호화키·보존/파기/접근 주체·단기 복원 시험도 정한다. 상시 복원 서버는 만들지 않는다.

## 6. 바로 진행할 순서와 승인 경계

먼저 기존 결정의 재승인 질문을 반복하지 말고 다음 최소 작업을 구체화한다. 미결정 환불 정책, 구 URL 유지 기간, 고객별 연결/예외 등은 의존 작업이 시작되기 전에 묻는다.

1. 최신 코드·checkout·계정/환경 구분을 확인하고 구현 계획·완료 조건·역할 경계를 기록한다. 일반 파일/로컬 테스트와 안전한 읽기 점검을 진행한다.
2. StepPay 원장 조회 가능 여부와 고객별 읽기 중단 수단/신규 가입 차단 경로를 확인한다. 아직 StepPay 로그인/API 권한은 검증되지 않았다. 운영 변경을 하기 전 대상·효과·잔여 권리 보존·복구 방법을 제시한다.
3. 신규 비PII 정책과 고객 1곳의 읽기 전용 dry-run을 준비해 실제 복사 범위·차단 항목·이미지 검수 난이도를 확인하고 비용/공수를 재산정한다.
4. 최소 이전/검증 도구, 결제 혜택/유예/첫 결제 경로를 테스트와 함께 보완한다. 운영 과금은 테스트 증거를 대신하지 않는다.
5. 고객 신청·가입·소속/권리·기존 대상 충돌 검수 후 승인된 고객별 manifest로 실제 이전한다. 건수/관계/checksum/개인정보 제외/재실행/고객 수정 차단을 검증한다.
6. 고객 검수 뒤 발행·외부 링크 변경, 종료 전 자료 보관과 백업·복원·환불·미전환 고객 확인, 별도 종료 승인 순으로 진행한다.

**이 인계는 운영 실행 승인 확대가 아니다.** 실제 갱신 취소/환불/청구·신규 고객 적재·원본 편집/접수 중단·외부 게시/링크 변경·개인자료 외부 복사·유료 복원 자원 생성·서버/DB 종료는 대상과 효과가 고정된 기존 명시 승인을 확인하고, 없으면 사용자에게 구체적 실행안을 확인받는다. 이전 승인이나 CLI 접근 가능성을 모든 운영 행위의 승인으로 확대하지 않는다.

## 8. 완료 보고 기준

각 작업마다 코드/커밋·승인된 대상·실제 실행 여부·검증 근거·보류/실패·정리한 임시 접근/파일을 분리해 기록한다. dry-run/로컬 테스트를 운영 적재로 집계하지 않는다. ‘데이터 복사됨’, ‘고객 이용 시작’, ‘유료 전환’, ‘Opening 종료’를 각각 다른 단계로 보고한다.

첫 보고에는 (a) 그대로 재사용할 것, (b) 최소 추가 구현, (c) 지금 할 수 있는 읽기 점검, (d) 사용자 결정/승인이 필요한 운영 행위, (e) 기능 세션과 겹치는 파일을 적는다. 기존 7~12인일/350만~600만원은 폐기된 전체 사전 복사안의 예시이므로 새 범위 견적으로 재사용하지 않는다.
