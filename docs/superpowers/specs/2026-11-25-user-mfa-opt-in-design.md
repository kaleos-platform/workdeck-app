# 일반 사용자 2단계 인증 기본 꺼짐 + 계정 단위 켜기 (설계)

- 날짜: 2026-11-25
- 브랜치: `feat/sms-mfa` (base `origin/develop`)

## 의도

일반 사용자에게 인증 앱(TOTP)은 어렵다. 문자 인증은 Supabase Advanced MFA Phone 부가 기능 월 $75 + 발송비가 들어 지금 단계에선 과하다(보류).
지금은 모집 업무만 공개한 준비 단계라, **일반 사용자의 2단계 인증을 당분간 끄고**, 운영에서도 안전하게 테스트·내부 보호를 할 수 있도록 **계정 단위로 켤 수 있게** 한다.

## 목표

- 기본: 일반 사용자는 `requireAal2` 게이트(초대 ADMIN·구성원 변경·연동 정보·에이전트·AI 설정·비밀값 저장 등 25곳)를 인증 없이 통과.
- 계정 단위 「2단계 인증 필수」 플래그가 켜진 사용자만 지금처럼 인증 앱 요구.
- 어드민에서 켜기/끄기(감사 로그), 사용자 목록·구독 현황 목록에서 어디서 쓰는지 보인다.

## 비목표

- 문자(SMS) 인증 — 비용 문제로 보류.
- 작업 공간 단위 필수 설정 — 고객 요구가 생기면 별도.
- 사용자 본인이 스스로 켜고 끄기.

## 반목표 (이러면 실패)

- 운영자 어드민(`requireOperator`) 또는 비밀값 보기·env-secrets·어드민 platform google·recovery-key(`requireFreshAal2`)의 인증이 풀리는 것.
- 플래그를 일반 사용자가 API로 바꿀 수 있는 것.
- 배포 직후 내부(운영자) 계정 보호가 빈 시간이 생기는 것.

## 제약

- Prisma 변경은 `migrate dev`만, 운영 DB 직접 SQL 금지.
- 비상 해제 스위치 `ADMIN_REQUIRE_MFA=false` 동작은 그대로 유지.

## 접근 방식 (검토한 것)

| 안 | 내용 | 결과 |
|---|---|---|
| 문자 인증(Supabase phone factor) | 월 $75 + 국내 업체 연동 | 비용 과다로 보류 |
| 환경변수 하나로 일반 사용자 전체 끄기 | 단순, 계정별 테스트 불가 | 계정 단위 요구로 확장 |
| 계정 목록 = Vercel 환경변수 | 코드 최소, 바꿀 때마다 재배포·기록 없음 | 기각 |
| **계정 목록 = DB 플래그 + 어드민 토글** | 재배포 없이 즉시, 감사 로그 | **채택(에디)** |
| 작업 공간 단위 | 자산 보호엔 정확, 25곳 수정 | 기각(에디) — 나중 고객 요구 시 |

## 결정 사항 (에디 확정)

1. 일반 사용자 2단계 인증 기본 꺼짐. 운영자 어드민·비밀값 보기는 인증 앱 유지.
2. 계정 단위(사용자) 「2단계 인증 필수」 플래그, 저장은 DB, 어드민 사용자 상세에서 토글.
3. 어드민 사용자 목록·구독 현황 목록에서 사용 현황 표시.

## 설계

- **데이터**: `User.mfaRequired Boolean @default(false)`. 마이그레이션에서 이미 인증 앱을 등록(verified)한 계정은 `true`로 시작 (Claude 판단 — 배포 직후 내부 계정 보호 공백 방지. 모집 고객 중 등록 계정은 에디가 어드민에서 끌 수 있다).
- **운영자**: `platformRole = OPERATOR` 는 플래그와 무관하게 게이트에서 항상 인증 앱 요구 (Codex 지적 — 이후 승격 계정 포함).
- **평문 우회 경로**: 에이전트 생성·수정, 에이전트 토큰 발급, 비밀값 저장·허용 에이전트 변경은 계정 플래그와 무관하게 항상 인증 앱 (Codex 지적 — 토큰 발급으로 `/api/secrets/env` 평문을 받는 우회 차단). 모집 사용자가 에이전트 토큰을 쓰려면 인증 앱 등록 필요.
- **게이트**: `requireAal2()` — 비상 스위치 확인 후, 현재 사용자의 `mfaRequired`가 false면 통과(null). true면 기존 aal2 판정. `requireFreshAal2`·`requireOperator`는 변경 없음. 호출 25곳 시그니처 변경 없음.
  - 초대 감사 로그의 `aal` 기록(`isAal2Fresh`)은 그대로 실제 값을 남긴다.
- **설정 화면**: `MfaCard`는 `mfaRequired`가 false면 숨긴다 (Claude 판단 — 인증 앱을 안 쓰는 사용자에게 "미등록" 안내가 혼란).
- **어드민**
  - 사용자 상세: 「2단계 인증 필수」 켜기/끄기. 운영자만, `writeAuditLog`로 기록. 변경 API는 `requireOperator` 뒤.
  - 사용자 목록: 「2단계 인증」 칸(필수/꺼짐 + 인증 앱 등록 여부), "필수만 보기" 필터.
  - 구독 현황(공간별): 「인증 필수 구성원 N명」 칸.

## 빌더에게 남긴 것

- 인증 앱 등록 여부 조회 방법(`auth.mfa_factors` 읽기 전용 조회 등) — 저장소에 기존 조회 없음, 계획에서 정한다.
- 목록 칸·필터의 구체 위치·문구 — 기존 `users-table.tsx`·`subscriptions-client.tsx` 패턴과 `DESIGN.md`를 따른다(기존 패턴에 칸 추가라 `ui-plan` 미리보기 생략).
- `requireAal2`가 사용자를 읽는 방법(같은 요청의 세션 user id로 Prisma 조회) — 추가 DB 조회 1회 허용.
