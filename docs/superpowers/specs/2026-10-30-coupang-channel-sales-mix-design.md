# 쿠팡 채널 관리 — 매출 구성(광고비 비중) 화면 설계

- 작성: 2026-10-30
- deck: `coupang-ads` (표시 이름만 「쿠팡 채널 관리」로 변경, id·경로 유지)
- 상태: 설계 승인 대기

## 1. 의도

쿠팡 광고 관리 deck 을 「쿠팡 채널 관리」로 넓히는 첫 단계. 사용자는 **쿠팡 전체 판매 중 광고가 차지하는 몫**과 **광고 없이도 팔리는 상품**을 지속적으로 모니터링하며 채널을 운영하고 싶다. 광고 입찰·예산 관리 기능은 이미 있으므로 이번 범위가 아니다.

### 왜 "전체 − 광고 = 자연" 이 아닌가 (실측, 2026-10-30, 운영 DB 최근 31일)

| 항목 | 값 |
|---|---|
| 판매분석(VENDOR) 전체 매출 | 2,850만 |
| 광고 리포트 직접전환 매출(1일) 합 | 2,618만 (**92%**) |
| 광고 상품별 광고매출/전체매출 | 81 ~ 109% |
| 광고 옵션 ↔ 판매분석 옵션 결합 | 76/76 (100%) |

- 쿠팡은 광고 클릭 후 1일 내 구매를 광고 매출로 귀속한다 → 광고가 없어도 샀을 구매까지 포함. 차감 방식이면 광고 상품은 전부 "광고 의존", 미광고 상품만 "자연" 이 되어 **모니터링 가치가 없다**.
- 광고 전환은 **같은 상품의 다른 옵션 판매**까지 광고 집행 옵션에 귀속된다(1위 옵션 일별 대조: 광고 전환매출이 해당 옵션 단가의 배수가 아님). 옵션 단위로 빼면 음수가 나온다.

→ **결정(사용자 승인)**: 주 지표 = **광고비 비중 = 광고비 ÷ 전체 매출**(귀속 방식과 무관). 쿠팡 기준 광고매출 비중은 참고 지표. 판정 단위 = **상품**.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 기간별 쿠팡 전체 매출·광고비·광고비 비중과 그 추이를 한 화면에서 본다.
- 상품별로 광고비 비중과 매출 추이를 비교해 「광고 없이 판매」「광고 의존」 상품을 골라 본다.
- deck 이름을 「쿠팡 채널 관리」로 바꾸고 사이드바를 섹션으로 묶는다.

**비목표**
- 광고 입찰/예산 조정, 자연유입 유도(CRM·콘텐츠), 신규/기존 고객 구분.
- 쿠폰 등록·효과(다음 작업), 데이터 연결 허브 이전(그 다음 작업).
- 새 데이터 수집. 기존 광고 리포트(`AdRecord`) + 판매분석(`InventoryRecord` VENDOR) 만 쓴다.

**실패 조건 (동작해도 실패)**
- 화면 숫자가 쿠팡 광고 대시보드·판매분석 화면과 같은 기간에서 어긋나는데 이유가 표시되지 않는다.
- 쿠팡 기준 광고매출 비중을 "광고 효과"로 오해하게 만든다(라벨·툴팁으로 귀속 방식 명시 필수).

## 3. 데이터

모두 **Workspace 스코프**(`resolveWorkspace`), 브랜드 운영 deck 구독과 무관.

| 지표 | 출처 | 비고 |
|---|---|---|
| 전체 매출·판매수량 | `InventoryRecord` `fileType='VENDOR_ITEM_METRICS'`, `revenue30d`·`salesQty30d` 를 `snapshotDate` 별 합 | 두 컬럼은 이름과 달리 **일자별 값**(메모리 `reference_vendor_salesqty_daily`). 트래픽 0 인 날 행수가 줄어도 판매 지표는 온전 |
| 상품 묶음 | VENDOR 의 `productId`·`productName` | optionId → productId 매핑도 VENDOR 에서 |
| 광고비 | `AdRecord.adCost` 를 `optionId` → VENDOR `productId` 로 묶어 합 | 기간 내 VENDOR 에 없는 광고 옵션은 "판매 데이터 없음" 상품 행으로 남김(현재 0건) |
| 쿠팡 기준 광고매출 | `AdRecord.revenue1d` 합 | 참고 지표. 100% 초과 가능 → 그대로 표시 |
| 이전 기간 | 같은 길이 직전 구간 | 기존 대시보드 `prevMetrics` 와 같은 규칙 |

### 3.1 확정 규칙 (빌더 점검 후 보강, 운영 DB 실측 2026-10-30)

- **판매방식 필터 없음** — 로켓그로스 + 판매자배송 모두 포함("쿠팡 전체 판매"). 31일 실측: 로켓그로스 2,209만 / 판매자배송 642만(22%). 광고는 두 방식 모두에 붙는다.
- **분모 컬럼 = `revenue30d`(「최근 매출」, 취소 차감 후)**. 실측 `revenue30d = totalRevenue + totalCancelAmt`(취소 음수) 정확히 일치. `totalRevenue` 쓰지 않음.
- 취소·반품 행(`revenue30d < 0`, 31일 35행)은 **필터하지 않고 그대로 합산**. 판매수량도 순합. `quantity > 0` 류 필터 금지(반품이 사라짐).
- **광고비 KPI = 상품 표 광고비 합**이 되도록, VENDOR 에 매칭 안 되는 광고 옵션·`optionId` null 행도 KPI 에 포함하고 표에 「판매 데이터 없음」 행으로 남긴다. (실측: null 0행, 미매칭 0건 — 방어 규칙)
- optionId → productId 매핑은 **기간 내 최신 snapshotDate 행 기준**(실측: 120일 내 상품 이동 0건 — 방어 규칙).
- **부분 수집**: 기간 내 VENDOR 가 있는 KST 일수 < 기간 일수면 KPI 위에 "기간 중 N일 판매 데이터 없음" 안내(실측 90일 중 89일).
- **VAT**: 광고비·매출을 리포트 값 그대로 쓴다(별도 보정 없음, 설계자 판단). 설명 툴팁에 "광고비는 쿠팡 광고 리포트 기준" 명시.
- **주 경계**: 월요일 시작 KST 주. 기간 양 끝 불완전 주도 그대로 표시(라벨에 기간 표기). 설계자 판단.
- **이전 기간에만 매출이 있던 상품**: 현재 매출 0 → 기본 숨김 규칙에 따라 숨김. "매출 0 포함" 토글 시 이전 기간 이름으로 표시(이름 출처가 이전 기간 행뿐인 경우 대비).
- 참고 실측: 31일 전체 광고비 1,174만 / 매출 2,850만 → **전체 광고비 비중 약 41%**. 상태 임계값(§5)은 출시 후 실제 분포를 보고 조정 가능.

- 날짜 축은 KST 일자. 기존 `src/lib/coupang-ads/queries.ts`·`src/lib/date-range.ts` 의 기간/KST 처리를 재사용한다.
- 판매 수집이 꺼진 워크스페이스(`CollectionCredential.collectVendorSales === false`) 또는 기간 내 VENDOR 0행: 빈 상태 + "설정에서 판매 수집 켜기" 링크.

## 4. 화면 (시안 A 승인)

경로 `/d/coupang-ads/sales-mix`. 기존 쿠팡 광고 대시보드 구성(기간 칩 7/30/90일 + 날짜 입력, KPI 카드 + 이전 대비)과 워크덱 UI 원칙(`.codex/skills/workdeck-ui/SKILL.md`: 중립색, 상태 pill, compact 표, sticky header, tabular number)을 따른다. 시안 파일: 브레인스토밍 `sales-mix-layout-v2.html`(A안).

1. **KPI 카드 4개**: 전체 매출 / 광고비 / **광고비 비중** / 쿠팡 기준 광고매출 비중(참고 툴팁). 각 카드에 이전 기간 대비.
2. **주별 추이**: 주별 전체 매출 막대 + 광고비 비중 선.
3. **상품 표**: 상품명 · 전체 매출 · 판매수량 · 광고비 · 광고비 비중 · 비중 변화(%p) · 매출 변화(%) · 쿠팡 기준 광고매출 비중 · 상태 pill.
   - 상단 필터 칩: 전체 / 광고 없이 판매 / 광고 의존 (건수 표시).
   - 정렬: 기본 전체 매출 내림차순, 헤더 클릭 정렬.
   - 매출 0 상품 기본 숨김.
   - 행 클릭 → 우측 패널: 해당 상품 일별 매출 막대 + 광고비 선 + 옵션별 판매 내역(옵션 단위 광고 귀속은 표시하지 않음).
4. 페이지 설명문에 "광고비 비중 = 광고비 ÷ 판매분석 전체 매출. 쿠팡 기준 광고매출은 클릭 후 1일 내 구매를 모두 포함" 명시.

## 5. 상태 판정 (설계자 판단 — 상수 한 곳에 둠)

기간 내 상품 단위:

- 🟢 **광고 없이 판매**: 광고비 비중 ≤ 5% **그리고** 판매수량 ≥ 기간 일수(하루 평균 1개 이상)
- 🔴 **광고 의존**: 광고비 비중 ≥ 20%
- ⚪ **중간**: 그 외 (판매수량 기준 미달 포함)

임계값은 `src/lib/coupang-ads/sales-mix.ts`(가칭) 상수. 설정 UI 는 요청 시 추가.

## 7. 구현 범위 메모 (빌더 재량)

- 서버 집계 함수 1개(기간 → KPI·주별·상품 행) + API 라우트 또는 서버 컴포넌트 초기 데이터. 기존 대시보드처럼 서버 초기 조회 + 클라이언트 기간 변경 재조회 패턴 권장.
- 집계는 SQL group by(Prisma `groupBy` 또는 `$queryRaw`). 상품 수 수백 건 수준.
- 테스트: 집계(옵션→상품 묶음, 이전 기간, 광고 옵션 미매칭), 상태 판정 경계값 단위 테스트. 화면은 기존 dashboard 테스트 스타일.
- 검증: `npm run lint`, `npm run typecheck`, 관련 jest, `npm run build`, 로컬 dev 화면 확인(맥북 SSH 포트포워딩 안내 포함).
