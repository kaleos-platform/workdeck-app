# SEO·GEO 2단계 — 검색 등록 태그·채용 공고 JobPosting·공고 하단 링크

- 작성: 2026-11-23, 브랜치 `feat/seo-phase2`(origin/develop 기준)
- 상위: grill 합의 2026-11-20(GA4 1단계 완료 #1554~#1595). SEO·GEO 는 모집 관리 집중.

## 목표

1. 검색엔진 소유 확인을 코드 수정 없이 환경 변수로 넣을 수 있게 한다(네이버 서치어드바이저·Bing·구글 HTML 태그 방식 대비).
2. 고객 공개 채용 공고(`app.workdeck.work/p/[uuid]`)가 구글 채용 검색에 노출되도록 **JobPosting 구조화 데이터**와 메타(설명·OG·canonical)를 넣는다.
3. 공고 하단에 작은 「워크덱으로 만든 채용 페이지」 링크(→ 모집 관리 랜딩, `utm_source=job_page`)로 유입 경로를 만든다.

## 현재

- `app/(marketing)/layout.tsx` 에 `metadataBase` 만, `verification` 없음. `app/layout.tsx` 에도 없음.
- `/p/[uuid]` `generateMetadata` 는 `title` 만. 구조화 데이터 없음. 하단에 워크덱 표기 없음.
- `/p/*` 는 app 호스트(`app.workdeck.work`)에서 서빙, robots 는 `/p/*/apply` 만 차단(공고 본문 허용).
- 공용 `JsonLd` 컴포넌트(`src/components/marketing/json-ld.tsx`) 존재.

## 변경

### 1. 소유 확인 태그 (환경 변수)

- `src/lib/marketing/seo.ts` 에 `siteVerification(): Metadata['verification']` — `GOOGLE_SITE_VERIFICATION`, `NAVER_SITE_VERIFICATION`(other: `naver-site-verification`), `BING_SITE_VERIFICATION`(other: `msvalidate.01`) 중 설정된 것만. 값은 서버 env(빌드 시 정적 메타로 들어감 — NEXT_PUBLIC 불필요, 서버 컴포넌트 metadata).
- `app/(marketing)/layout.tsx` metadata 에 `verification: siteVerification()`. 앱 도메인(`app.workdeck.work`)은 등록 대상 아님(마케팅 사이트만 검색 등록).
- 구글은 **Search Console 도메인 속성 + DNS TXT** 를 권장(workdeck.work·app·admin 하위 도메인 전체를 한 번에 확인 → `/p/*` 공고 색인 상태도 같은 속성에서 봄). HTML 태그 env 는 대안.
- 빈 문자열·공백 값은 무시(빈 meta 출력 금지).

### 2. 공고 JobPosting + 메타

- 신규 `src/lib/hiring/job-posting-jsonld.ts` — 순수 함수 `buildJobPostingJsonLd(input)`:
  - `title`(공고 제목), `description`(HTML 문자열: 포지션별 담당 업무·자격 요건·우대, 텍스트 블록 본문 — 비어 있으면 JSON-LD 를 내지 않음; Google 필수 필드), `datePosted`(publishedAt ?? createdAt, ISO), `validThrough`(closingDate 있으면 그날 23:59:59 KST ISO), `hiringOrganization: { @type: Organization, name: Space.name }`, `jobLocation`(공고 매장의 `roadAddress` 별 `Place > PostalAddress{ streetAddress, addressCountry:'KR' }`; 주소가 하나도 없으면 JSON-LD 를 내지 않음 — 필수), `employmentType`(포지션 jobType 중복 제거 매핑: FULL_TIME→FULL_TIME, PART_TIME→PART_TIME, CONTRACT/FREELANCER→CONTRACTOR, INTERN→INTERN), `baseSalary`(포지션이 1개이고 payAmount·payFrequency(HOURLY/DAILY/WEEKLY/MONTHLY/YEARLY) 있을 때만 `MonetaryAmount{currency:KRW, value:{QuantitativeValue, value, unitText: HOUR|DAY|WEEK|MONTH|YEAR}}`), `directApply: true`, `identifier` 생략.
  - 내보내는 조건: status ACTIVE && 마감 전 && 미리보기 아님. 마감·CLOSED·DRAFT 미리보기는 출력하지 않는다(만료 공고 노출은 구글 정책 위반).
  - 입력 문자열은 그대로 JSON 직렬화(`JSON.stringify` → `JsonLd` 가 `</script>` 이스케이프하는지 확인, 안 하면 `<` → `<` 치환 추가).
- `app/p/[uuid]/page.tsx`:
  - `loadPosting` 에 `space: { select: { name: true } }` 추가(공고의 공간 이름 = 회사명).
  - `generateMetadata`: ACTIVE/CLOSED 면 `description`(포지션·지역 요약 1줄, 120자), `alternates.canonical`(`buildAppUrl('/p/'+uuid)`), `openGraph{ title, description, url, type:'website' }`. CLOSED 는 `robots: { index: false }`(만료 공고 색인 제외). DRAFT·ARCHIVED 기존대로.
  - 본문에 `<JsonLd data=... />` (조건 충족 시).
- 비밀·PII: 담당자 연락처(암호화 필드)·지원자 정보는 넣지 않는다. 매장 도로명 주소·공간 이름·직무 정보만(이미 공고 화면에 공개된 값).

### 3. 공고 하단 링크

- `/p/[uuid]` 페이지 맨 아래 작은 회색 링크 「워크덱으로 만든 채용 페이지」 → `buildMarketingUrl('/recruiting?utm_source=job_page&utm_medium=referral&utm_campaign=public_posting')`, `rel="noopener"`, 새 탭 아님. 미리보기(DRAFT)에서는 숨김 여부: 그대로 표시(무해).
- 지원 폼(`/p/[uuid]/apply`)에는 넣지 않는다(지원 흐름 방해 금지).
- 마케팅 랜딩에 도착하면 기존 `wd_src` first-touch 쿠키·GA4 page_view(utm 허용)로 집계된다.

## 범위 밖

- 모집 관리 콘텐츠·FAQ(3단계), llms.txt 개편.

## 검증

- 단위: `buildJobPostingJsonLd` — 필수 필드, 주소 없음/설명 없음 → null, employmentType 매핑·중복 제거, baseSalary 단일 포지션만, validThrough KST 23:59:59, `</script>` 문자열 이스케이프.
- `siteVerification` — 미설정/빈값 → undefined, 설정 값만 출력.
- 페이지 테스트(있으면): ACTIVE 에 script[type=application/ld+json] 존재, CLOSED·마감·DRAFT 미리보기엔 없음, 하단 링크 href.
- 로컬 dev 에서 공고 1개 렌더 → JSON-LD 를 Google 리치 결과 테스트 형식으로 육안 확인(구조 검증은 배포 후 Search Console 「리치 결과 테스트」 URL 검사).
- tsc·eslint·관련 jest·`npm run build`.

## Codex 검토 반영 (2026-11-23) — 지적 7건, 반영 7 (에디 결정 2건 포함)

1. [critical] JSON-LD XSS: 공용 `src/components/marketing/json-ld.tsx` 에서 `JSON.stringify(data).replace(/</g, '\\u003c')`(리터럴 `<`, `>`·`&`·U+2028/2029 도 이스케이프). 회귀 테스트: 제목에 `</script><img onerror>` 넣은 렌더 HTML 을 파싱해 script 가 1개·탈출 없음 확인.
2. [high] 테넌트 필터: 본문과 **같은 필터를 거친 데이터만** JSON-LD·메타에 쓴다 — 페이지에서 이미 `spaceId === posting.spaceId` 로 거른 positions·stores 를 빌더 입력으로 넘긴다(빌더가 DB 를 직접 읽지 않음). `generateMetadata` 도 같은 필터 함수 사용. 교차 Space 연결 행 테스트.
   - 주소 노출(에디 결정 11-23): **공고 화면의 매장 이름 옆에 도로명 주소(상세 주소 제외)를 표시**하고 같은 값을 jobLocation 에 쓴다(화면=마크업 일치).
3. [high] 지원 경로: 페이지가 실제 렌더하는 button/image 블록 링크 중 **내부 지원 폼(`/p/{uuid}/apply`)이 있을 때만** JobPosting 출력, `directApply: true`. 외부 링크만 있거나 지원 링크가 없으면 JobPosting 을 내지 않는다.
4. [high] 단일·가시 정보: **공간 필터 후 포지션이 정확히 1개이고, positions 블록이 화면에 렌더되는 공고만** 대상. description 은 화면에 보이는 값만(담당 업무, 근무 요일·시간, 급여, 경력, 학력, 텍스트 블록 본문) — 화면에 안 보이는 자격 요건·우대 사항은 넣지 않는다. 복수 포지션 공고는 범위 밖(개별 URL 설계 후).
5. [medium] 중복 호스트: 운영 분리 호스트에서 `workdeck.work/p/*` → `app.workdeck.work/p/*` 308 리디렉트(쿼리 보존, proxy 의 기존 app 전용 경로 처리 방식 따름). 양 호스트 테스트.
6. [medium] 하단 링크(에디 결정 11-23): 기본 표시 + **전체 끄기 스위치 `HIRING_PUBLIC_POWERED_BY=off`**. 새 탭(`target=_blank rel=noopener`)으로 열어 지원자가 공고를 떠나지 않게 한다. 지원 전환 영향은 GA4 `utm_source=job_page` 유입·모집 관리 지원 수로 모니터링.
7. [medium] 만료·조기 마감: CLOSED·마감일 경과 시 JSON-LD 제거 + `robots noindex`. Indexing API 는 이번엔 쓰지 않는다(공고 수가 적고 validThrough 로 충분) — 긴급 제거는 Search Console 「삭제」 도구(담당: 에디, 절차를 이 문서에 남김). 상시 공고(마감일 없음)는 validThrough 생략.
