# 업무 추가 체험 안내와 전액 취소 구독 상태 복구

사용자 보고: 업무 추가 시 체험 여부가 보이지 않으며, 취소한 테스트 결제가 구독 해지 예정으로 남는다.

원인과 확정한 수정:

- 내 워크덱은 entitlement의 allowed만 받아 체험·면제·유료·결제 중지를 구분하지 못했다. reason과 업무별 종료 시각을 전달해 기존 확인 창·카드에 표시한다. 최초 추가는 7일 무료 체험, 재추가는 원래 종료일 유지, 체험 후 자동 결제 없음. 종료일 표시는 기존 KST formatter를 재사용한다.
- 웹훅은 청구만 REFUNDED로 바꾸고 구독 아이템을 끝내지 않았다. PG API에서 CANCELED를 재확인한 뒤 같은 transaction에서 해당 청구의 업무를 종료한다. 남은 업무가 없으면 구독을 CANCELED로 바꾸고 다음 결제일을 지운다. 이미 REFUNDED인 청구도 같은 절차로 복구할 수 있다.
- 부분 취소를 전액 환불로 표시하지 않는다. 과거 주기 취소, 이후 추가한 업무, 별도 PAID/PENDING 청구가 보장하는 업무, 다른 유료 업무는 보존한다. 다른 결제 주기의 전액 취소에 대한 기간 배분은 이번 범위에 포함하지 않는다.
- 전액 환불 후 종료된 구독은 해지 예정일 대신 마지막 결제 전액 취소 안내를 표시한다. 체험·면제는 별도 entitlement에 따른다.

운영 진단은 READ ONLY로 수행했다. 고객 이메일·결제 키·DB 자격증명은 이 문서에 기록하지 않는다. 추가 결제나 PG 환불 요청은 실행하지 않는다. 배포 뒤 보고된 단일 주문의 웹훅을 재검증하여 기존 상태를 복구한다.

검증 계획:

- 관련 UI·라우트 회귀, 로컬 PostgreSQL transaction·중복 이벤트·다른 업무 보존 검증.
- typecheck/lint/build, 합성 데이터 1440px/390px 화면·확인 창 검증, 독립 코드 리뷰.
- 기존 승인된 develop/main 배포와 운영 도메인 확인 후 보고된 결제 상태 복구 확인.

참고: 현재 checkout에는 DESIGN.md가 없어 기존 shadcn 컴포넌트·상태 배지·KST formatter를 재사용한다.

검증 기록

- 관련 단위·UI 회귀 113개 통과.
- 로컬 DB: 신규 환불 회귀 6개 + 기존 업무별 체험·면제 13개 + 보장가 16개 통과. PG는 mock이며 운영 DB는 쓰지 않았다.
- 독립 리뷰의 최초 item 생성 시각·진행 중 결제·해지 예약 경합을 각각 실패 테스트로 재현하고 수정했다. 최종 리뷰 승인.
- 실제 컴포넌트 합성 fixture 1440px/390px: 신규 체험·기존 체험·재추가 확인·환불 완료 8상태에서 가로 넘침·브라우저 오류 없음.
- 로컬 전체 lint 오류 0(기존 경고 65). 동시 작업으로 로컬 타입 검사 메모리 부하가 커 실행을 중단했다. 최종 타입 검사·production build는 PR의 Vercel build를 통과해야 배포한다.
