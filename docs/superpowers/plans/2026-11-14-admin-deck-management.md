# 덱별 업무 관리 화면

/grill-me에서 확정한 범위:

- 사용자·구독 현황·결제는 공통 메뉴 유지. 업무 관리는 덱 전용 운영 기능만 모은다.
- 모든 서비스 덱을 표시하고 기능 없는 덱에는 `관리 기능 없음`을 표시한다. Workdeck은 공간/플랫폼 진입점이므로 덱 목록에서는 제외한다.
- 카드에서 기능으로 바로 진입한다. 빈 덱 상세 페이지나 중간 선택 화면은 만들지 않는다.
- 기존 템플릿·첨부 정리 URL과 API·데이터·운영자/MFA 가드를 유지한다.

구현 순서:

- [x] UI 와이어프레임은 합의된 카드 구조를 기록한다(`docs/design/plans/admin-deck-management/`).
- [x] `DeckManagement` 컴포넌트: 기존 DECK_META에서 실제 덱을 가져와 이름순으로 표시. 모집 관리에는 두 기능, 나머지는 비대화형 빈 상태. 기능 링크가 없는 카드는 클릭되지 않는다.
- [x] `/admin/decks` Server Component: 자체 requireOperator/MFA 확인 후 화면 렌더링.
- [x] 공통 nav와 대시보드 진입점을 `업무 관리`로 변경. 기존 두 전용 링크는 공통 메뉴에서 제거.
- [x] 템플릿 목록·상세와 첨부 정리 이력에 업무 관리 경로 표시. 기능 URL과 관련 쿼리는 유지.
- [x] 목록·권한·내비게이션·기존 첨부 정리 회귀 검증. typecheck/lint/build + 1440px/390px 브라우저 표시·키보드 검증.
- [ ] 독립 리뷰 후 기존 승인된 develop→main 배포 흐름으로 운영 반영.

검증 기록:

- 관련 Jest 3 suites / 16 tests 통과: 전체 덱·빈 상태·기존 링크, 신규 페이지 권한/MFA, 공통 내비게이션·대시보드, 첨부 정리 회귀.
- production build 통과(`/admin/decks` 라우트 포함). typecheck 통과. lint 오류 0건(기존 경고 65건).
- 실제 컴포넌트를 번들한 로컬 fixture를 Ego Lite에서 1440px/390px로 검증: 덱 5개, 빈 상태 4개, 빈 카드 링크·tab stop 없음, 가로 넘침 없음, 두 기능 링크 높이 64px, Tab 순서 정상. 운영 고객 데이터·세션을 사용하지 않음.
- 독립 read-only 리뷰 승인: 중대·중요 이슈 없음.
