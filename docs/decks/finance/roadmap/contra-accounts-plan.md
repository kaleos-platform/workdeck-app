## 최종 방식

| 계정 타입      | 집계 섹션 | 반대 방향 거래(환불)               |
| -------------- | --------- | ---------------------------------- |
| 수익(INCOME)   | 수입      | 출금(고객 환불) → 그 수입에서 차감 |
| 비용(EXPENSE)  | 지출      | 입금(환급) → 그 비용에서 차감      |
| 이체·미분류 등 | 현금 방향 | —                                  |

- 환불은 **원래 계정에 그대로 분류**한다(예: 고객 환불 출금 → `온라인 판매정산`, 광고비 환급 입금 → `광고비`). 별도 환불 계정은 필요 없다.
- 순현금흐름(수입 − 지출)은 방향 기준과 항상 같다. 수입/지출 사이에서 금액만 이동한다.
- 단일 소스: `src/lib/finance/contra.ts`(`fixedSectionOf`, `cashSection`). 현금흐름 표·대시보드·Sankey·거래내역 합계와 direction 필터·export가 모두 이 규칙을 쓴다.
- 손익계산서·공헌이익(`pnl-metrics`, `pnl-statement`)은 원래부터 계정 타입 기준 자연부호라 변경 없음.

## 분류 UI

- 계정과목 선택 팝업의 기본 탭은 거래 방향 기준(출금 → 비용, 입금 → 수익).
- 반대 타입 탭(`refundType`)도 열리고, 고르면 "그 수입/비용에서 차감됩니다" 안내가 뜬다.
- 분류 확인 팝업의 "이 분류를 규칙으로 저장"은 기본 해제.

## 오분류 방지

PR #331의 출금→수익 차단 가드는 제거했다. 대신 환불이 자동으로 번지지 않게 막는다.

- `learnRule`: 계정 섹션과 반대 방향 분류는 규칙으로 학습하지 않는다.
- `loadSpaceRules`: 반대 방향 규칙은 자동분류에 쓰지 않는다.
- AI 추천(`staging/[id]/suggest`): 방향에 맞는 타입만 후보로 낸다.

## 폐기된 초안(차감 계정 방식)

`FinCategory.isContra`로 매출환입·매입환출 같은 차감 계정을 두는 방식이었다. 비용 쪽 환불마다 대분류별 차감 계정이 필요하고, 영업외비용 하나로 몰면 매출총이익·공헌이익·영업이익이 과소 계상되는 문제가 있어 대체했다. `isContra` 컬럼 정리는 `finance-followups-plan.md` 참고.
