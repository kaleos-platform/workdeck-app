# iPhone 네이티브 미러링 검증 — 2026-11-15

> 이 문서는 초기 네이티브 선택기 시험 당시 기록이다. 이후 로그인·운영 접수·다운로드·용량/개수 경계를 추가 검증했다. [최신 운영 iPhone 검증 기록](2026-11-15-production-iphone-qa.md)과 구분한다.


사용자가 iPhone 직접 조작을 요청하고 Mac의 손쉬운 사용·화면 기록 및 iPhone 미러링 연결을 완료한 뒤 수행했다. iPhone 11(`iPhone12,1`), 기기 조회 iOS 27.2에서 Safari를 사용했다. UDID·기기 이름·자격 증명은 기록하지 않는다.

## 조작 방식

Mac의 iPhone 미러링 창에 CoreGraphics 마우스 클릭·스크롤과 네이티브 키보드 이벤트를 전달하고 창 영역만 캡처해 확인했다. Web Inspector의 DOM 클릭·값 주입으로 대체하지 않았다. 사람이 iPhone 유리에 손가락을 댄 시험이나 iOS 소프트웨어 키보드 각 키의 조작 시험과는 구분한다. Xcode/Appium/WDA runner는 사용하지 않았다. 기존 Mac 창과 사용자 Safari 탭을 추가로 열거나 닫지 않았다.

## 실제 확인 결과

- 운영 로그인 화면에서 이메일 필드를 누르고 `workdeck-qa@example.invalid`를 입력해 화면 반영을 확인했다. iOS 암호 자동완성 패널이 나타났지만 저장된 자격 증명을 사용하지 않고 닫았다. 합성 입력값은 지웠으며 로그인 버튼을 누르지 않았다.
- 기존 QA 공개 지원 URL `https://app.workdeck.work/p/4b87bce9-0306-4c84-aeb6-ae2203a9628c/apply`를 네이티브 Safari 주소 입력으로 열었다. 공고 상태·지원서 양식·고객 자료는 변경하지 않았다.
- 실제 스크롤로 필수 항목과 첨부·동의·제출 영역까지 이동했다. 관찰한 구간에서 가로 잘림이나 넘침은 보이지 않았지만 DOM 폭 수치 측정 또는 모든 방향/확대 상태의 보장은 아니다.
- 파일 입력을 눌러 iOS의 사진 보관함·촬영·파일 선택 메뉴와 실제 파일 선택기를 열었다. 기기에 이미 있던 합성 `workdeck-qa-sample.pdf`(선택기 표시 593바이트)만 선택하고 열기를 눌렀다. 폼에 해당 파일명이 표시됨을 확인했다. 개인 파일 탐색·신규 파일 생성·기존 QA 파일 삭제는 하지 않았다.
- 폼의 X 버튼으로 첨부를 제거해 선택 상태가 사라진 것을 확인했다. 파일 선택기를 다시 열어 취소(X)한 뒤에도 파일 없는 상태로 폼에 복귀했다.
- 개인정보 동의는 체크하지 않고 지원서 제출 버튼은 누르지 않았다. 마지막에 Safari를 `https://app.workdeck.work/login`으로 복원하고 빈 이메일 입력을 확인했다.

## 초기 오류와 해석

초기에는 Mac 제어·화면 기록 권한이 없었고 미러링이 iPhone 사용으로 시간 초과됐다. 사용자가 권한·연결을 완료한 뒤 네이티브 제어가 가능해졌다. URL 입력 직후 이동 키를 너무 빨리 보내 서버를 찾지 못한 사례는 입력 반영을 확인하고 이동하는 방식으로 수정했으며 로그인과 QA 페이지가 정상 열렸다. 앱 또는 기기 DNS 결함으로 판정하지 않는다. Safari 축소 주소바의 첫 탭은 확장만 할 수 있으므로 주소 편집 상태를 시각적으로 확인하고 입력했다.

## 이 초기 시험에서 확인하지 않은 범위

실제 로그인·지원서 저장·Storage 업로드/다운로드 왕복, 카카오톡·메일 발송, 20 MiB 최대 용량, 여러 파일·사진·카메라·다른 파일 제공자, 회전·확대·소프트웨어 키보드·VoiceOver 및 사용자 손가락 조작은 시험하지 않았다. 파일 선택·제거는 폼의 클라이언트 상태 확인이며 네트워크 캡처로 POST 0건을 독립 집계한 결과는 아니다. 검토한 파일 onChange 구현은 클라이언트 파일 검증과 상태 갱신만 하며 업로드는 제출 흐름에 있다. 운영 제출이나 업로드를 재현했다는 주장을 하지 않는다.
