# 지원서 업무값 읽기 대조 계획

2026-10-21. 승인된 이전 검증의 후속이다. 암호문과 updatedAt을 포함한 기존 targetHash는 재암호화만으로 달라질 수 있다. 기존 hash 검사를 유지하면서 저장된 이전 판단과 현재 업무값이 같은지 별도로 검사한다. 이 검사는 재이전·충돌 해제·hash 재설정을 승인하지 않는다.

## 계약

- 기존 `POST /api/worker/hiring-migration-audit`에 `verifyApplications: string[]` 옵션을 추가한다. 중복 없는 원본 지원서 ID 1~7개만 허용하며 페이지 옵션과 함께 쓰지 못한다.
- 기존 두 고객 allowlist·OWNER 확인·worker 소속 검사·READ ONLY transaction을 재사용한다. 대상은 해당 고객 원장의 지원서에만 한정한다.
- 원장 sourceHash와 입력 복구를 검증한 뒤 현재 대상 identity/소속, 부모·직무·매장, 업무 상태·메모·유입 정보·날짜·응답, 첨부 메타데이터, 복호화한 표준 개인정보와 파생 HMAC/마스킹을 대조한다.
- 암호문 bytes·IV·updatedAt·새로 생성됐던 UUID·첨부 createdAt은 의미 비교 기준으로 사용하지 않는다. 기존 physical targetHash 일치 여부는 별도로 보고한다. 첨부 bytes 자체는 파일 감사의 범위다.
- 응답에는 집계 건수와 고정된 차이 항목 이름만 포함한다. 개인정보, 암호문, hash 값, 원문, 대상 ID는 응답/로그로 보내지 않는다. 키는 운영 런타임에 두며 로컬로 내보내지 않는다.

## 구현·검증 순서

- [x] 비교 테스트: v0→v1 재암호화·시간 변경은 의미 일치/physical 불일치, 실제 PII·상태·관계·첨부·응답 변경은 불일치, 손상·다른 고객·복구 실패는 차단한다.
- [x] `application-target-audit.ts`에 기존 복구/PII/hash helper를 사용한 읽기 비교를 구현한다.
- [x] route 테스트를 먼저 실패시키고 옵션 검증·소속 제한·READ ONLY·응답 비노출·기존 페이지 동작을 확인한다.
- [x] 최소 route 분기로 비교를 연결한다. 새 쓰기 경로·의존성·스키마는 추가하지 않는다.
- [x] 관련 테스트·TypeScript·lint·build와 변경 리뷰 후 PR을 준비한다.
- [ ] 운영 반영 후 승인된 피크페이 7건을 호출해 집계만 기록한다. 다른 항목까지 같다는 근거 없이 재암호화만이 원인이라고 단정하지 않는다.

## 로컬 검증 결과

- 기존 검증 API/runtime 기본선 2 suites/16 tests 통과.
- 새 비교 module 부재와 선택 조회 옵션 미지원 실패를 먼저 확인했다.
- 최종 관련 10 suites/179 tests 통과. 정상 첨부·직무·매장과 ID가 같은 채 다른 고객/다른 공고 소속으로 바뀐 관계도 검증했다.
- TypeScript 통과. 전체 lint 오류 0·기존 경고 63, 최종 변경 파일 lint 오류/경고 0.
- `next build --webpack` 통과. 개발 환경변수만 사용했으며 운영 DB 쓰기는 수행하지 않았다.
- 독립 리뷰에서 부모 행의 실제 소속 검사가 빠진 점을 보완한 뒤 재리뷰에서 중요한 추가 문제는 없었다.
- 운영 7건의 비교 결과는 아직 미검증이며 별도 실행 후 기록한다.
