## 합성 대량 조회 후속 검증

고정 source·운영 관측 기준 `a9316c2b`를 사용해 앱의 기본 목록 인덱스와 정렬을 재현한 일회용 localhost PostgreSQL에서 5만 행을 생성했다. 공간 2개, 대상 공간 48,000행 중 활성 47,520행, 1% soft delete와 10행 단위 동일 시각을 포함했다. 실제 앱 schema와 운영 인덱스는 변경하지 않았다.

각 3회 EXPLAIN ANALYZE의 서버 실행시간 중앙값: 첫 50행 0.046ms, offset 40,000은 10.926ms, 이름 hit/miss 5.946/5.297ms, 이름 또는 전화 끝4자리 hit/miss 0.646/5.740ms, 이름 또는 전체전화 hit/miss 3.126/5.721ms, count 5.359ms였다. 문장별 5초 제한을 넘은 경우는 없었다. 첫/깊은 페이지는 공간·생성시각 인덱스를 사용했고 이름 미적중·OR 미적중·count는 Seq Scan이었다.

이는 작은 tuple과 동일 로컬 캐시에서 수행한 핵심 SQL 근사 시험이다. 실제 Prisma 발행 SQL, posting 관계·blacklist 조회, 선택적 근무지/직무/날짜/단계 조건, JSON 크기·pool 대기·복호화·권한·네트워크·화면 전체를 포함하지 않는다. hit 집합이 중첩되어 OR 양쪽이 분리된 경우의 합집합 정확성도 별도 검증하지 않았다. count 계획의 Actual Rows=1은 aggregate 결과 1행이며 일치 지원서 1건이라는 뜻이 아니다. 운영 SLA나 미래 대량 부하를 보장하지 않으며 이 시험만으로 새 인덱스를 도입하지 않았다.

스크립트의 finally 출력만으로 삭제 성공을 단정할 수 없어 주 agent가 별도로 임시 접두사의 디렉터리와 해당 PostgreSQL 서버를 조회했고 각각 0건임을 확인했다. 그 외 사용자 프로세스·파일럿·운영 DB를 변경하지 않았다.

후속 점검에서 iPhone 미러링 재연결과 운영 로그인 화면 복원을 확인했다. 저장된 계정의 암호 자동완성 제안은 사용하지 않고 닫았으며 로그인 제출을 하지 않았다. 전용 QA 계정 확인이 없어 관리자 로그인·다운로드는 여전히 미검증이다. 공고 이미지 3MiB 초과 사전 차단과 안내 수정은 별도 PR #1443에서 검증 중이며, 지원서 첨부 최대20MiB 제한과는 별개다.

## 이미지 용량 수정 운영 반영

PR #1443이 main `b27e021fa8008b148dca4f8506cd4f7859c77a8f`에 병합됐다. 공고 이미지 안내를 파일당3MB 이하로 수정하고 3MiB 초과 이미지는 Base64 전송 전에 차단한다. 관련 테스트173개·타입 검사·공개 설정을 사용한 독립 전체 빌드와 CI migration-lint/rls-lockdown/visual-smoke가 통과했다. lint는 오류0·경고64였다. 운영 배포 `dpl_HPCtKNRWhzehxqPJNhE5yybUeQWS` READY와 app.workdeck.work alias 일치, login HTTP200을 확인했다. 운영 인증 화면의 실제 이미지 업로드는 아직 별도 미검증이다. 사용자가 전용 QA 계정 로그인을 진행한다고 답했으며 완료 통지 전까지 iPhone 입력을 중단했다. 저장된 계정 자격은 사용하지 않았다.

## QA 계정 관리자 로그인 후속

사용자의 로그인 완료 통지 후 iPhone 네이티브 미러링에서 인증된 내 워크덱, 테스트 Space의 모집 관리 진입, 전체 지원자 목록을 확인했다. 전체/각 단계 지원자 수는 모두0건이고 다운로드 가능한 첨부가 없었다. QA 계정의 관리자 화면 진입은 확인했으나 첨부 다운로드는 미검증이다. 다른 QA Space 또는 합성 자료 준비 여부를 사용자에게 확인했으며 고객 지원서 열람·생성·수정·발송은 수행하지 않았다.

## 운영 iPhone 후속 검증 완료

사용자가 QA 계정 로그인과 현재 테스트 Space의 합성 자료 생성을 승인했다. 운영 HTTPS에서 작은 PDF와 정확한20MiB PDF 접수, 초과1B 선택 차단, 두 파일 항목 동시접수 및 관리자 각 PDF 다운로드를 네이티브 조작으로 확인했다. 메일 설정 두 개 모두 끈 화면을 확인하고 이메일 없이 접수했다. 합성 공고2개는 모두 마감하고 지원서3건·첨부4개는 보존했다. 임시 공급 서버·디렉터리는 정리·부재 확인했다. 상세와 시험 한계는 [운영 iPhone 검증 기록](2026-11-15-production-iphone-qa.md)을 따른다. 앞선 관리자 로그인·다운로드 미검증 기록은 당시 상태이며 이번 확인으로 보완한다.

## 전체 첨부3개 제한 실기기 확인

추가 합성 공고에서3개 선택 허용·4번째 선택 차단·기존3개 유지·거부 후3개 접수 성공·관리자 항목 연결과 세 번째 다운로드를 확인했다. 최종 합성 공고3개 모두 마감, 지원서4건·첨부7개를 보존했다. 상세는 운영 iPhone 검증 기록의 전체 첨부 개수 후속 검증을 따른다. 제품 코드·발송·고객 자료는 변경하지 않았다.
