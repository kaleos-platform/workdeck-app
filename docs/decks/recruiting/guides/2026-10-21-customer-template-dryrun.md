## 소속과 링크

모든 참조 파일은 해당 고객 소유 또는 활성 공통 샘플/기본 콘텐츠에서 공유한 정확한 file key임을 확인했다. Opening의 복사 동작은 원본 파일 key를 유지하므로 file 행의 현재 소유자만으로 오판하지 않는다. 미확인 타 고객 파일은 사용하지 않았다.

원본 지원 링크 61개는 Opening에서도 새 공고의 지원 URL로 치환하는 링크이며, Workdeck `linkType:form`으로 변환했다. 새 공고에 템플릿을 적용하면 해당 공고 지원 링크를 사용한다. 원본 대표 이미지·이름·날짜·섹션 배열은 보존한다. 내부 Space FK는 기존 계정 연결 검증용이며 공간 선택 UI를 추가하지 않는다.

## 실행 보호와 검증

최종 manifest는 각 템플릿 원본 row hash와 `contentHash` 39개를 포함한다. `contentHash`는 본문 순서·scene·이미지 경로·링크·대표 이미지·대상 scope를 묶는다. 원본/변환 checksum 및 적용 코드 5개 파일의 SHA256도 고정한다. 실제 실행 직전에 재준비한 결과가 승인 manifest와 다르면 업로드 전에 중단한다.

기본 CLI는 dry-run이며 실제 쓰기는 명시적 `--apply`·production project·production-pilot 환경 검증을 요구한다. 파일은 결정적 경로·`upsert:false`·전후 checksum으로 복사한다. 템플릿은 OWNER 확인 후 정상 모델을 transaction으로 생성한다. 기존 저장값이 같은 경우 재사용하고 고객 수정·고객 소속·샘플·본문 충돌은 덮어쓰지 않는다. 중간 실패 시 이미 생성한 자료를 자동 삭제하지 않고 멈춘다.

- migration 10 suites / 184 tests 통과. 원본 key 대응 차단과 동일 파일 집합 내 scene 연결 변경 감지 회귀 테스트를 포함한다.
- TypeScript 통과, 전체 lint 오류 0·기존 경고 63, 변경 파일 lint 오류/경고 0, 최종 webpack build 통과.
- 개발 DB 합성 자료만으로 nested create·JSON/날짜·재실행·수정 충돌·OWNER 검증 후 transaction rollback. 합성 Space/템플릿/블록 잔여 0건, Storage 쓰기 0건.
- 독립 코드 리뷰의 이미지 key 검증과 최종 본문 hash 지적을 수정했다. 운영 적용 CLI가 선택하는 DB 경로도 READ ONLY로 연결·OWNER 검증했고 대상 bucket 조회를 확인했다.
- 임시 환경변수는 회수했다. 원본 RDS 임시 규칙은 finally에서 회수했고 해당 설명의 잔여 0건을 독립 확인했다.

## 필요한 승인과 후속 확인

기존 환경변수 승인에 데이터 변경이 제외되어 있으므로 **피크페이 템플릿 39건과 본문 블록 417개 신규 생성, 이미지 최대 350개 복사**는 별도 승인 전 실행하지 않는다. 대상은 기존 `devops@workdeck.work` 계정이다. 이미 같은 파일이 있으면 checksum 확인 후 재사용한다. 이 요청에는 기존 공고/지원서 삭제·덮어쓰기, 운영 공고 발행, 지원 접수, 알림 발송, Opening 서비스 종료가 포함되지 않는다.

승인 후 metadata/Storage 대조와 실제 UI 적용 확인을 수행한다. 전체 고객 전환·알림 운영 방식·원본 URL/이미지 유지·서비스 종료 조건은 별개로 남아 있다. 현재 결과를 전체 이전 완료로 간주하지 않는다.
