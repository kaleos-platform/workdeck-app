# 배송 데이터 상단 통합 탐색 영역

## 배경

배송 데이터 관리 화면에서 통합 검색은 페이지 제목 아래에 있고, 배송 묶음 기간 필터는 왼쪽 패널 안에 있다. 같은 데이터를 탐색하는 두 수단이 떨어져 있어 사용자가 필터 위치를 다시 찾아야 하고, 왼쪽 패널의 좁은 폭 때문에 날짜 입력도 답답하게 표시된다.

## 목표

- 배송 묶음 기간 설정과 통합 검색을 하나의 공통 탐색 영역으로 묶는다.
- 공통 탐색 영역을 `완료된 배송 묶음` 패널 밖, 좌우 작업 영역 상단에 배치한다.
- 기존 배송 묶음 조회와 전체 주문 검색의 동작 범위는 변경하지 않는다.

## 확정 배치

페이지 제목 바로 아래에 `배송 데이터 필터` 영역을 둔다.

- 넓은 화면: 기간 프리셋과 날짜 범위를 왼쪽에, 통합 검색을 오른쪽에 한 줄로 배치한다.
- 좁은 화면: 컨트롤이 겹치지 않도록 기간과 검색을 자연스럽게 줄바꿈한다.
- 기간 영역: `7일`, `30일`, `이번달`, `지난달`, 시작일, 종료일을 유지한다.
- 검색 영역: 기존 검색어와 지우기 동작, 300ms debounce, 최소 검색 길이 2자를 유지한다.
- 왼쪽 패널: `완료된 배송 묶음` 제목, 접기 버튼, 배송 묶음 목록만 남긴다.

## 상태와 데이터 흐름

`ShippingOrdersPage`가 기간 상태와 검색 상태를 소유한다.

1. 초기 기간은 KST 기준 최근 7일이다.
2. 프리셋 또는 날짜 입력이 바뀌면 새 기간을 `BatchList`에 전달한다.
3. `BatchList`는 전달받은 기간으로 완료된 배송 묶음을 다시 조회한다.
4. 새 기간에 선택된 묶음이 없으면 기존처럼 선택을 해제한다.
5. 검색어가 2자 이상이면 기존처럼 전체 주문 검색 결과를 표시한다.

기간 조건은 완료된 배송 묶음 목록에만 적용한다. 통합 검색은 기존처럼 전체 기간을 대상으로 하며, 두 기능을 시각적으로 합치되 검색 API 의미는 바꾸지 않는다.

## 오류 및 상태 처리

- 배송 묶음 조회 실패, 요청 경합 방지, 빈 결과, 삭제 후 재조회 동작은 기존 구현을 유지한다.
- 검색 중에도 상단 통합 탐색 영역을 유지해 검색어를 지우거나 기간을 미리 변경할 수 있게 한다.
- 날짜 입력은 기존 native `input type="date"`를 재사용한다.

## 접근성 및 반응형

- 공통 영역에 `배송 데이터 필터` 접근 가능 이름을 제공한다.
- 기존 검색 input의 `aria-label`과 접기·펼치기 focus 복원을 유지한다.
- 작은 화면에서는 검색 input이 사용 가능한 전체 폭을 차지한다.
- 새 색상이나 별도 UI dependency를 추가하지 않고 기존 Button, Input 스타일을 사용한다.

## 검증 기준

- 통합 탐색 영역이 좌우 작업 영역보다 먼저 렌더링된다.
- 기간 컨트롤이 `완료된 배송 묶음` 패널 안에 남아 있지 않는다.
- 기간 변경 시 `BatchList`가 해당 시작일·종료일로 다시 조회한다.
- 검색어 2자 이상에서 기존 검색 결과가 표시된다.
- 검색을 지우면 선택된 배송 묶음 작업 영역으로 복귀한다.
- desktop과 좁은 화면에서 컨트롤이 겹치거나 잘리지 않는다.

## 범위 제외

- 기간 조건을 통합 검색 API에 적용하는 변경
- 검색 결과 화면 구조 변경
- 배송 묶음 및 주문 목록 API 변경
- 새로운 날짜 선택 라이브러리 도입
