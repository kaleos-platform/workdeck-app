# 배송 주문 검색 결과 컬럼 개선

> 대상 deck: seller-hub (`/d/seller-ops/shipping/orders`)
> 작성일: 2026-09-24
> 상태: 설계 승인 완료, 구현 전

## 배경과 문제

통합 주문 검색 결과 표는 9개 컬럼과 `min-w-[1350px]` 고정 최소 폭을 사용한다. 일반적인 desktop 작업 영역에서는 오른쪽의 `결제금액` 컬럼이 화면 밖으로 밀려나며, 가로 스크롤바도 최대 50개 결과의 맨 아래에 있어 사용자가 즉시 발견하기 어렵다.

검색 결과에 필요한 정보는 유지하되, 서로 연관된 정보를 한 셀에 묶어 가로 폭을 줄여야 한다.

## 목표

- 일반적인 desktop 작업 영역에서 주요 7개 컬럼과 `결제금액`을 한 화면에 표시한다.
- 받는분·전화번호와 주문번호·주문일을 각각 2줄로 묶어 정보 손실 없이 폭을 줄인다.
- 좁은 화면에서는 기존처럼 가로 스크롤을 허용해 내용이 겹치거나 잘리지 않게 한다.
- 상세보기에서 전체 주문 정보를 확인하는 기존 흐름을 유지한다.

## 확정된 구성

검색 결과 표를 다음 7개 컬럼으로 구성한다.

| 컬럼            | 표시 내용             | 표시 방식                                   |
| --------------- | --------------------- | ------------------------------------------- |
| 받는분·전화번호 | 받는분 이름, 전화번호 | 이름을 첫 줄, 전화번호를 둘째 줄에 표시     |
| 주문번호·주문일 | 주문번호, 주문일      | 주문번호를 첫 줄, 주문일을 둘째 줄에 표시   |
| 주소            | 배송 주소             | 한 줄 말줄임, 전체 값은 기존 `title`로 확인 |
| 상품명          | 상품명                | 한 줄 말줄임, 전체 값은 기존 `title`로 확인 |
| 배송메모        | 배송메모              | 한 줄 말줄임, 전체 값은 기존 `title`로 확인 |
| 판매채널        | 판매채널              | 한 줄 말줄임                                |
| 결제금액        | 결제금액              | 우측 정렬, 줄바꿈 방지, 숫자 폭 고정        |

표의 최소 폭은 약 `1080px`로 낮춘다. 이 폭은 현재 배송 데이터 화면의 넓은 주문 작업 영역에서 7개 컬럼을 모두 보이게 하면서 주소와 상품명의 판독 가능한 폭을 유지하는 기준이다.

받는분 셀의 기존 상세보기 버튼은 유지한다. 행을 선택하는 새 동작이나 별도 상세 패널은 추가하지 않는다.

## 반응형과 접근성

- 표 컨테이너의 `overflow-x-auto`를 유지해 `1080px`보다 좁은 화면에서는 가로 스크롤을 제공한다.
- 2줄로 묶은 보조 정보는 작은 글자와 muted 색상을 사용하되 읽을 수 있는 명암을 유지한다.
- 결제금액은 `tabular-nums`와 우측 정렬을 적용해 행별 금액 비교가 쉽도록 한다.
- 상세보기 버튼의 기존 접근 가능한 이름과 keyboard 동작을 유지한다.
- 정보가 잘리는 셀은 기존 native `title` 패턴을 유지하며 새 UI dependency를 도입하지 않는다.

## 상태와 데이터 흐름

검색 요청, 최대 50건 표시, loading, 오류, 빈 결과, 상세 주문 조회 흐름은 변경하지 않는다. API response와 주문 데이터 타입도 변경하지 않는다. 이번 변경은 `OrderSearchResults`의 header와 row 렌더링에만 적용한다.

## 검증 기준

- header가 7개 그룹 컬럼으로 렌더링된다.
- 각 결과 행에서 받는분과 전화번호, 주문번호와 주문일이 각각 같은 셀의 두 줄로 표시된다.
- 결제금액 컬럼이 마지막 컬럼에 우측 정렬로 표시된다.
- 표 최소 폭이 기존 `1350px`보다 줄어 일반 desktop 작업 영역에서 결제금액까지 보인다.
- 좁은 viewport에서는 표 컨테이너의 가로 스크롤 fallback이 유지된다.
- 상세보기 버튼과 상세 dialog의 전체 정보가 기존과 동일하게 동작한다.
- 검색 loading, 오류, 빈 결과 UI가 회귀하지 않는다.
