# 키워드 성과 데이터 연결 설계 (광고 검색어 · 네이버 키워드도구 · 검색 순위)

> 대상 deck: seller-hub (`/d/seller-ops`)
> 선행: `prd/keyword-ux-revamp.md`, 키워드 게이트 개선·순위 추적 PR #1158·#1165·#1168·#1170·#1172(develop), 순위 보류 PR #1178(미머지)
> 상태: **설계 + 위원회 판정 반영** (2026-10-25). §5-0 검증 후 §2 착수.

## 왜

키워드를 바꿔도 **잘 바꿨는지 판단할 근거가 없다.**

- `KeywordMaster.score` 는 사람이 체크하는 boolean 10개(`src/lib/sh/keyword-score.ts`)다 — 「쿠팡 자동완성 등장」 「연관검색어 등장」 같은 항목을 손으로 조사해 넣는다. 검색량·노출·주문 같은 수치가 없다.
- 변경 효과 비교(`src/lib/sh/change-effect.ts`)는 판매량과 검색 순위로 설계했지만 순위 수집 소스가 막혔다(아래 §4).

필요한 건 세 가지 숫자다.

| 질문                                      | 필요한 숫자             | 소스                            |
| ----------------------------------------- | ----------------------- | ------------------------------- |
| 이 키워드로 고객이 실제로 찾고 사는가     | 키워드별 노출·클릭·주문 | 쿠팡 광고 리포트 (§2)           |
| 이 키워드를 찾는 사람이 얼마나 많은가     | 월간 검색량·경쟁도      | 네이버 검색광고 키워드도구 (§3) |
| 우리 상품이 그 검색 결과 몇 위에 보이는가 | 자연 순위               | 아이폰 수집기 (§4)              |

## 1. 현재 보유 자산 (2026-10-25 prod 읽기 전용 실측)

- **`AdRecord.keyword`** — 워커가 매일 쿠팡 광고 리포트를 적재한다. 최근 90일:
  - 고객 실검색어 **8,618개**, 18,674행, 노출 64만, 주문(1일) 1,340건, 옵션 85개
  - 30일 주문 상위: 「여성 팬티」 38 · 「팬티」 23 · 「브라탑 나시」 12 · 「여성 브라탑나시」 8 · 「여성 질염 팬티」 6
- **`loadAdTermsForProduct`** (`src/lib/sh/ad-terms-query.ts`) — 이미 상품별 광고 검색어를 집계해 **SOP 위저드**와 AI 상품명 초안 근거로 쓴다. 한계:
  - 귀속이 **캠페인 단위**(`AdCampaignProductMap`). 키워드가 있는 캠페인 4개 중 3개만 매핑돼 있고, 한 캠페인에 상품이 여럿이면 검색어가 상품 구분 없이 섞인다.
  - **기간 창이 없다**(전체 누적). 최근 변화가 묻힌다.
  - 등록 키워드와 **나란히 보이지 않는다** — 위저드 안에서만 노출.
- **`KeywordRankSnapshot`** 테이블·순위 페이지·효과 패널 — develop 에 있고 `RANK_TRACKING_ENABLED=false`(#1178)로 숨김.

## 2. 1단계 — 쿠팡 광고 검색어를 키워드 관리에 연결

새 외부 연동 없음. 이미 있는 데이터를 **보이는 곳**과 **판단에 쓰는 곳**으로 옮긴다.

### 2.1 귀속을 옵션 단위로

캠페인 매핑 대신 `AdRecord.optionId`(쿠팡 외부 옵션ID) → `external-option-bridge.ts` 3-hop 브리지 → `InvProductOption` → 리스팅/채널상품. 공헌이익 집계(`margin-query.ts`)가 이미 같은 브리지를 쓴다. 팬아웃은 기존 규칙대로 `MapItem.quantity` 비례 배분.
캠페인 매핑은 브리지가 비는 옵션의 폴백으로만 남긴다.

### 2.2 화면

| 위치                                                | 표시                                                          |
| --------------------------------------------------- | ------------------------------------------------------------- |
| 키워드 칩 (`KeywordEditor`, 기존 `rankBadges` 자리) | 최근 30일 노출·주문 — 예: 「노출 2.1천 · 주문 6」             |
| 키워드 카드 하단 「발굴 후보」                      | 주문이 났는데 등록 키워드에 없는 검색어 상위 N개, 원클릭 추가 |
| 키워드 카드 「정리 후보」                           | 등록했지만 30일 노출 0 인 키워드                              |
| 변경 이력 효과 패널                                 | 판매량 옆에 「바꾼 키워드」의 광고 노출·주문 전후 14일        |

### 2.3 한계 (문서·화면에 명시)

- 광고를 돌린 키워드만 보인다. 자연 검색으로만 유입된 검색어는 모른다.
- 자동 캠페인이 실검색어를 넓게 잡지만, 광고 입찰이 꺼진 상품은 데이터가 없다.
- 리포트의 주문은 광고 귀속 주문이다 — 전체 판매와 다르다.

### 2.4 작업량

스키마 변경 없음. 서버 집계 함수 1개(기간·옵션 귀속) + API 1개 + 칩·카드·효과 패널 UI.

## 3. 3단계 — 네이버 검색광고 키워드도구 API

### 3.1 무엇

`GET https://api.searchad.naver.com/keywordstool?hintKeywords=...&showDetail=1`
→ 키워드별 월간 검색수(PC·모바일), 월평균 클릭수·CTR, 경쟁정도(`compIdx`), 연관 키워드 목록.

개발자센터 검색 API(2026-07-31 쇼핑 종료, HUB 이관)와 **별개 서비스**다. 2026-10 기준 동작 사례가 있으나 공식 확인은 착수 시 실호출로 한다.

### 3.2 쓰임

- `KeywordMaster` 후보에 검색량·경쟁도 자동 채움 → 수동 boolean 점수 일부(「구매 의도」 제외)를 수치로 대체하거나 병기.
- 연관 키워드로 후보 확장 → 2단계 발굴 후보와 합쳐 중복 제거(`keyword-normalize.ts` 3키).
- 화면에는 「네이버 기준 수요」로만 표시한다. 쿠팡 수요 대리지표로 쓰지 않는다(위원회 판정).

### 3.3 필요한 것

- 네이버 검색광고 계정(광고비 없이 개설 가능) + API 라이선스: 고객 ID·액세스 라이선스·비밀키. 발급은 Aside 로, 키는 `.env.local`·Vercel 에 직접 입력(채팅 금지).
- 서명: HMAC-SHA256(`timestamp.method.uri`) 헤더. 호출 한도는 착수 시 확인.
- 캐시: 같은 키워드는 월 1회면 충분(검색량은 월 단위). `KeywordMaster` 에 `searchVolume`·`compIdx`·`volumeFetchedAt` 컬럼 추가(마이그레이션 1건).

### 3.4 보류: 데이터랩·쇼핑인사이트(NAVER API HUB)

계절 추세·성별/연령 비중. 키워드 판단보다 기획용이라 후순위.

## 4. 4단계 — 검색 순위 수집기 (아이폰, 자사 실험 전용)

### 4.1 경위

| 시도                                               | 결과                                                                                      |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 네이버 쇼핑 검색 API                               | 2026-07-31 종료(개발자센터 공지 32973), HUB 에도 없음                                     |
| 쿠팡 비로그인 Playwright(데스크톱, 휴대폰 회선 IP) | 첫 요청 Access Denied                                                                     |
| 유료 순위 API                                      | 국내 B2B API 없음, 해외 스크래핑 API 는 쿠팡 100위 시 스페이스당 월 ~$1,350 + 약관 리스크 |
| **아이폰 공기계 Safari + Mac mini USB**            | 쿠팡·네이버 모두 1페이지 정상 수집                                                        |

### 4.2 실측으로 확정된 사실

- 조작: `pymobiledevice3`(uv tool) 의 Web Inspector 세션(비-automation). `navigator.webdriver=false`. `ios_webkit_debug_proxy` 는 iOS 17+ 에서 탭을 못 찾는다.
- 탭 선택은 **`WIRTypeWebPage` + URL 있는 탭만** — 네이버가 ServiceWorker 항목을 목록 끝에 추가해 `pages[-1]` 이 거기 붙어 멈췄다.
- `Runtime.evaluate` 가 `awaitPromise=false` 라 비동기 결과는 `window` 변수에 담아 폴링한다.
- **쿠팡**: 비로그인은 모바일·데스크톱 모두 **1페이지만**(`page=2` → 결과 없음). 순위 소스는 RSC `products[]` — `link`(`/vp/products/{id}`) + `adBadgeArea.sponsored`. DOM 링크는 추천 위젯이 섞여 순서가 틀린다. 1페이지 자연 결과 약 51개 → **측정 깊이 50**.
- **네이버**: 비로그인은 쿠키 삭제 후 로그인 페이지로 튕김 → **별도 개인 계정 로그인**(스토어 판매자 계정 금지). 쇼핑 홈(`shopping.naver.com/ns/home`) 경유 후 검색. `__NEXT_DATA__` → `props.pageProps.compositeProducts.list[].item`: `rank`(자연, 광고는 별도 `lst*S`), `mallProductId`=스마트스토어 상품번호. 가격비교 묶음은 `lowMallList[].mallPid` 로 매칭(목록이 일부 판매처만 담을 수 있어 누락 가능 → 별도 errorCode). **`pagingIndex=2` 이동은 로그인 상태에서도 즉시 IP 일시 제한** → **측정 깊이 40**.
- AML 스마트스토어 `13762253244` 「머드팬티」: 3위(10-23) → 5위(10-25) — 매칭 검증 완료.
- 데이터: 쿠팡 검색 1회 ≈ 0.34MB + 이미지 ~90장, 네이버 1페이지 ≈ 0.15MB + 이미지. 키워드×2채널 ≈ 5~7MB 추정.

### 4.3 설계

- **분리 프로세스**: Mac mini 운영 워커(`workdeck-worker`)와 별개 launchd. USB·휴대폰·Python 장애가 광고·재고 수집에 닿지 않게.
- **휴대폰 쪽은 단순하게**: 키워드마다 이동 → 페이지 데이터에서 순서 목록만 추출해 서버로. 매칭·스냅샷 기록은 서버 TS.
- API: `GET /api/worker/keyword-rank/targets`(토큰 Space 범위, 오늘 미수집 키워드를 소스별 중복 제거), `POST /api/worker/keyword-rank/results`(키워드 1건씩). space 스코프 토큰만 허용.
- `collect-naver.ts` 의 이어받기·FAILED 재시도·슬롯·연속 실패 중단을 소스 무관 함수로 추출. API 예산 로직은 삭제. `naver-shopping.ts`(죽은 API)·cron 라우트 삭제.
- 소스별 깊이 상수(COUPANG 50, NAVER_SHOPPING 40) — 「N위 밖」 문구와 효과 패널 sentinel(현재 `OUT_OF_TOP100_RANK=101`)을 소스별로. enum `NOT_IN_TOP100` 은 유지(스키마 변경 없음).
- **출구 IP 가드**: 매 실행 전 휴대폰 페이지에서 ipify 조회 → `112.152.74.59`(집·운영 워커)면 쓰기 없이 중단. 핫스팟 재연결 중 집 Wi-Fi 로 붙은 사례가 실제로 있었다.
- **빈도·사람처럼**: 주 3회(월·수·금, 설정값), 시작 06:00~08:00 무작위, 검색 간격 20~60초, 8~12회마다 3~8분 휴식, 결과 화면 체류·분할 스크롤, 키워드 순서 섞기, 1회 실행 상한 60검색, 같은 탭·쿠키 유지. 제한·로그인·차단 화면이면 즉시 중단.
- 효과 패널 「관찰 중 n/14일」은 경과일이 아니라 **측정 횟수**도 함께 표시(주 3회면 14일에 ~6회).

### 4.4 운영 전제

- 공기계용 **데이터 SIM** 필요(현재 S26 핫스팟 의존). 7GB+1Mbps 알뜰폰(프로모션 0~7,900원 → 이후 2만원대)이면 충분.
- 아이폰: 자동 잠금 끔, 충전 연결, 쿠팡 사이트별 「데스크탑 웹사이트 요청」 켬, 네이버 로그인 유지.
- 휴대폰 1대 = 우리 스페이스 규모. 고객 스페이스 전체로 확장 불가 — 그때는 다른 소스가 필요하다.
- 비공식 수집이라는 약관 리스크는 남는다.

## 5. 진행 순서 (2026-10-25 위원회 판정 반영)

0. **검증 먼저(코드 전)**: 자사 상품 3~5개로 광고 실검색어 30일치에서 발굴·정리 후보를 직접 뽑는다. 운영자가 「채택하겠다」고 고르는 후보가 **5개 이상**이면 1번 착수, 미만이면 범위 재검토.
   - **결과(2026-10-25, 통과)**: 상품 3계열(모달 팬티·캡내장 브라탑·클렌징 패드). 발굴 8묶음(단어 약 15개), 정리 3묶음(9개) 모두 채택.
     - 채택 예: 항균(상품명은 「향균」), 학생·고등학생·중학생, 질염방지·통풍·중년·50대, 패드일체형, 흰색·흰나시, 선크림(등록은 「썬크림」), 유아용·초등, 클린징 오기.
     - 기각 예: 면팬티·국내산(모달 상품), 메리야스, 여름·레이어드, 리무버.
   - **§2 설계에 반영할 것**:
     - 검색어 원문이 아니라 **단어 단위**로 집계해야 쓸 만하다. 붙여 쓴 말(「여성팬티」)은 상품명·키워드 조각으로 분해되면 커버로 본다.
     - 귀속 단위는 옵션이 아니라 **상품 계열(채널상품)**. 옵션별로 보면 같은 키워드가 쪼개져 정리 후보가 거짓으로 늘었다.
     - **경쟁 브랜드명**(타사 브랜드 10여 개)이 발굴 상위를 오염시킨다. 제외 사전이 필요하다.
     - **표기 변형**(향균/항균, 썬크림/선크림)이 가장 값진 발견이었다.
     - 브리지 누락: 「모달 팬티 5장 세트」 계열(30일 주문 25)이 쿠팡 리스팅에 하나도 매칭되지 않았다. 캠페인 폴백 또는 리스팅 직접 매칭이 필요하다.
1. **§2 광고 검색어 연결** — 옵션 단위·30일 귀속, 칩 성과 표시, 발굴·정리 후보. 읽기 전용.
2. **§6 에이전트 주간 키워드 리뷰** — MCP 조회 툴 + 상품 단위 묶음 승인.
3. **§3 네이버 키워드도구** — 「네이버 기준 수요」로만 표시. 쿠팡 수요 대리지표로 쓰지 않는다(채널별 검색 문법이 달라 왜곡).
4. **§4 순위 수집기** — **자사 내부 실험으로만**. 고객 기능으로 내놓지 않는다(기기 1대·비공식 수집이라 확장·연속성 불가). SIM 확보 후, #1178 숨김·cron 제거를 이 작업에 합친다.

별도 deck·모듈로 분리하지 않는다. 키워드 관리 사이드바 섹션에 「키워드 리뷰」 페이지를 추가하고 데이터 계층은 공유한다. 리뷰에서 그 상품의 키워드·상품명 편집으로 바로 이어진다. 외부 명칭은 「검색 노출 최적화」로 붙일 수 있다.

각 단계는 워크트리 → develop → main 단계 릴리스. `KeywordRankSnapshot` 등 develop 에만 있는 스키마는 main 릴리스(별도 지시 + Codex 지적 2건 선점검) 전까지 운영에서 동작하지 않는다.

## 6. 사용자 시나리오 — 에이전트 활용

**경계 원칙**: 에이전트는 「읽기·계산·제안·판정」, 사람은 「상품명 변경·채널 반영·광고비」. 승인은 건별이 아니라 **상품 단위 묶음**(승인 큐 피로 방지).

### 6.1 매출 기대와 성공 지표

- 키워드 관리는 「수요 키워드가 상품명·키워드에서 빠진 상품」의 노출 누락을 메우는 범위에서만 매출을 올린다.
  - 효과 큼: 검색 유입 비중이 큰 일반명사 키워드, 상품명에 수요 키워드가 빠진 상품.
  - 효과 없음: 브랜드 검색, 가격·리뷰가 순위를 좌우하는 경우, 재고 부족.
- 전후 14일 비교는 인과 근거가 아니다(광고 유입 변동·가격·재고·계절성). 그래서 1차 성공 지표는 매출이 아니라 **「채택 가능한 후보 비율」**과 **「교란 없는 판정 건수」**.
- 상품명 변경 위험(재심사, 키워드 남용 패널티, 노출 점수 초기화)을 제안 카드에 명시한다.
