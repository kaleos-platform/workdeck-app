# 1. 미매칭이란

판매분석 상품 탭의 랭킹은 **상품을 알아낼 수 있는 판매만** 행으로 올린다. 상품을 특정하지 못한 매출은 추정으로 흩뿌리지 않고 맨 아래 `상품 미매칭` 행에 모은다. 그래서 **랭킹 합계 = 채널 탭 총매출** 이 성립한다. 단 상품 그룹 필터로 일부 그룹(기본값: 「배송 부자재」)을
제외 중이면 그만큼 작아지며, 제외 금액은 랭킹 헤더에 `배송 부자재 제외 중 ₩X` 로 표시된다.

헤더의 `상품 귀속 NN%` 배지가 그 비율이다. 현재 필터(기간·채널 유형) 기준으로 계산되므로 채널을 좁히면 값도 따라 변한다.

미매칭 행 부제에 **사유별 금액**이 표시된다. 사유마다 처리 방법이 다르니 먼저 이걸 본다.

| 부제에 뜨는 사유     | 뜻                                            | 처리 경로 |
| -------------------- | --------------------------------------------- | --------- |
| 로켓 외부코드 미매핑 | 쿠팡 SKU번호가 보관 위치 매핑에 없음          | §2        |
| 상품 미연결          | 주문 라인이 내부 옵션에 연결되지 않음         | §3        |
| 단종·삭제 상품       | 연결은 됐으나 상품이 INACTIVE / 옵션이 삭제됨 | §4        |
| 로켓 단종·삭제 상품  | 위와 같되 로켓 경로                           | §4        |

**2026-09-23 시점 실측** (정리 전 스냅샷): 귀속 99.4%, 최근 90일 매출 2억 856만원 중 미귀속 133만원 — 로켓 미매핑 1,010,110원(44코드) / 직배송 미매칭 256,100원(15줄) / 단종·삭제 69,001원(2옵션).

**2026-09-24 정리 후**: 최근 30일·이번달 귀속 **100%**, 90일 창에 단종·삭제 ₩57,334 만 잔류.

우선순위는 금액 순이 아니라 **소급 반영 여부**로 정하는 게 낫다. §2는 과거 데이터까지 즉시 복구되고, §3은 앞으로의 업로드에만 적용된다(§5 참조).

# 2. 로켓그로스 외부코드 미매핑 (1,010,110원)

## 원인

쿠팡 VENDOR 리포트의 SKU번호가 워크덱의 보관 위치 매핑(`외부코드 → 내부 옵션`)에 없다. 대개 **신규 출시 상품**이 매핑 등록 없이 판매되기 시작한 경우다.

## 처리 경로

```
사이드바 재고 → 보관 위치
  → 로켓그로스 위치 행 펼치기
  → 매핑 테이블에서 "매핑 추가"
  → 외부코드 입력 + 내부 옵션 선택 (+ 수량)
```

- 외부코드에는 **쿠팡 SKU번호**를 넣는다. 아래 목록의 `외부코드` 값이 그대로 들어갈 값이다.
- 1:N 세트 상품이면 구성 옵션을 여러 개 추가하고 각각 수량을 지정한다.
- 이미 그 외부코드에 매핑이 있으면 새로 만들지 말고 기존 매핑에 구성품을 **추가**해야 한다. 새로 만들면 기존 구성이 통째로 교체된다.

재고 대조 화면의 미매칭 옵션 팝업에서도 같은 작업을 할 수 있다.

## 반영 시점 — 소급된다

로켓 매출은 조회할 때마다 VENDOR 원본 레코드에 매핑을 다시 적용한다. 따라서 **매핑을 오늘 등록하면 과거 기간의 판매분석도 즉시 귀속된다.** 재수집·재업로드 불필요.

실제로 2026년 8월에 매핑을 대량 백필했더니 7월 로켓 귀속률이 35% → 99%로 소급 상승했다.

# 3. 직접배송 라인 미매칭 (256,100원 / 15줄)

## 원인

업로드된 주문의 상품명이 채널별 상품명 사전(alias)에 없어서 내부 옵션에 연결되지 않았다. 채널이 붙은 새 상품명, 사은품, 협찬 건에서 주로 발생한다.

## 처리 경로

```
사이드바 배송 → 주문 목록 (또는 배송 등록)
  → 해당 주문 행의 상품명 아래 노란 "상품 옵션 매칭" 배지 클릭
  → 팝업에서 내부 상품·옵션 선택
```

- 매칭된 라인은 **초록색 트리**로, 미매칭은 **노란색 배지**로 보인다. 색만 보고 훑으면 된다.
- 주문에 판매채널이 지정돼 있어야 매칭 버튼이 활성화된다. `미매칭 (채널 필요)` 로 보이면 채널부터 지정한다.
- 세트/묶음이면 구성 옵션을 여러 개 지정할 수 있다.

**여러 건을 한 번에**: `설정` 화면의 alias 일괄 등록 카드에서 CSV/TSV 로 붙여넣는다. 형식은 `channelId, aliasName, type, targetId` (`type` = `listing` 또는 `option`). 다만 다중 구성품 세트는 CSV로 안 되고 팝업에서 개별 등록해야 한다.

## 반영 시점 — 소급되지 않는다

매칭 팝업에서 만든 alias 는 **앞으로 업로드되는 주문에만** 적용된다. 이미 저장된 과거 주문을 다시 훑어 재매칭하는 기능은 없다. 즉 **팝업 클릭 1회 = 그 라인 1건 + 앞으로의 업로드**다.

위 7줄은 클릭 7번이면 끝난다. 하지만 **같은 상품명이 앞으로도 계속 들어올 것**이므로, 매칭해두면 다음 달부터는 자동으로 붙는다. 그게 이 작업의 진짜 값어치다.

# 4. 삭제된 옵션 / 비활성 상품 (69,001원 / 2개)

기간 내에는 팔렸는데 그 후 옵션이 삭제되거나 상품이 `INACTIVE` 로 바뀐 경우다. 랭킹에서 제외하되 매출은 미매칭 버킷에 남긴다.

| 옵션                           | 수량 | 사유          |
| ------------------------------ | ---- | ------------- |
| 크림드 60매 + 20매 세트 / 기본 | 3    | 상품 INACTIVE |
| 선 클렌징 패드 개별포장 / 60매 | 9    | 옵션 삭제됨   |

**대부분 그대로 두는 게 맞다.** 단종·정리한 상품이 과거 랭킹에 다시 올라오면 오히려 방해가 된다. 지금도 팔고 있는데 실수로 비활성화한 거라면 상품 관리에서 상태를 `ACTIVE` 로 되돌리면 된다.

# 5. 우선순위 정리

1. **로켓 매핑 44건** — 소급 반영되므로 과거 지표까지 한 번에 정확해진다. 잠옷 세트 4코드부터.
2. **직배송 7줄** — 금액은 작지만 alias 가 쌓여 앞으로의 자동 매칭률이 올라간다.
3. **협찬 8줄** — 재고 흐름을 맞출 때만.
4. **삭제·비활성 2건** — 보통 그대로 둔다.

전부 처리하면 귀속률은 99.4% → 100% 에 근접한다. 다만 **신규 상품이 나올 때마다 로켓 매핑이 비는 건 구조적**이라, 배지가 100%에서 조금씩 내려가는 건 정상이다. 신상품 출시 직후 매핑 등록을 루틴에 넣는 쪽이 사후 정리보다 싸다.

# 6. 참고 — 왜 미매칭을 배분하지 않나

미매칭 매출을 상품 비중대로 흩뿌리면 숫자는 깔끔해지지만, **이미 잘 팔리는 상품이 자기 실적을 과대평가받는다**. 그 상태로 발주·광고 판단을 하면 편향이 그대로 증폭된다. 그래서 워크덱은 귀속 실패를 감추지 않고 별도 행으로 드러낸다. 배지가 100%가 아닌 건 버그가 아니라 정직한 표시다.
