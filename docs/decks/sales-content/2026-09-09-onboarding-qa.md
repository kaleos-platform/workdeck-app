# 자료 기반 온보딩 검증

## 실제 공개 자료 검증

- 홈페이지 및 공개 카테고리 3개에서 중복 제거 후 상품 26개 확인: 환경교육 13개, 추천 굿즈 5개, 컨설팅 8개. 검증 시 추가 페이지 링크는 없었다.
- 네이버 모바일 블로그 목록은 서버 HTML에 글 링크가 없었다. 공개 RSS에서 동일 블로그 대표 글 20개를 발견했다. 실제 게시글 본문 2,953자에서 소재·환경교육·기업 거래 정보를 확인했다.
- `node scripts/verify-sales-content-import.cjs`로 상품 62(그린 펠트 수납박스)를 실제 Gemini API에 전달했다. DB 및 워크스페이스 설정은 변경하지 않았다.
- 최종 이미지 결과: 상세 이미지 27개 요청 / 27개 성공 / 44개 분할 이미지 / warnings 없음. 이전의 HTML 텍스트 전용 입력과 달리 소재·S/M/L 규격·맞춤 스티커·메시지 카드·주문조건·ESG 자료 제공 내용을 추출했다.
- 추출 결과는 판매자가 페이지에 기재한 내용을 정리한 AI 초안이다. 인증번호·가격·납기·최소 주문 수량·탄소저감 증빙은 공개 콘텐츠 제작 전 검토 대상이며, 독립적인 사실 검증 결과가 아니다.

## 자동 검증 범위

- URL 정규화: Cafe24 상품·카테고리 변형 중복 제거, 일반 URL 식별 query 보존, 추적 query 제거, 페이지 이동 유지.
- SSRF: 기존 safe-fetch 회귀 테스트. HTML/이미지 다운로드 동일 가드 사용.
- 실패 및 상한: 잘린 HTML 실패, 문서 길이·이미지 개수·이미지 읽기 실패 안내, 이미지 전용 상품 처리.
- 생성: 전체 상품 5개 제한 제거, 자료별 입력 예산, 개별 상품 분석 후 재개, 긴 출처로 customFields 50개를 넘지 않음.
- 저장: 동일 상품의 URL 표현과 상품명이 달라도 복제하지 않음, 상세 근거 보존, 거래 단위 저장.
- UI: 여러 URL, 계속 분석, 중지, 실패 표시, 전체/Shift 선택, customFields 저장, 빈 tone 처리, 저장 후 편집 잠금, 재분석 시 최신 브랜드 유지.

검증 명령: 관련 Jest 12 suites / 113 tests, `npm run typecheck`, `npm run lint`, `npm run build -- --webpack`.
기본 Turbopack 빌드는 제한된 실행 환경에서 진행되지 않아 종료하고 webpack으로 전체 production 빌드를 검증했다.
lint는 저장소 기존 warning이 있으며 error는 없다.

## 브라우저 검증 한계

로컬 production 서버에서 온보딩 URL 접근 시 로그인으로 정상 리다이렉트했다. E2E 로그인 계정이 없어 인증 후 실제 DB 저장·desktop/mobile 화면 검증은 실행하지 않았다. 실제 DB에 미닝랩 자료를 자동 등록하지 않았다.

스캔형 PDF OCR은 이번 범위에서 지원하지 않는다. 텍스트형 PDF·Markdown을 지원하며 읽을 수 없는 PDF는 실패 안내를 제공한다. 탭이 열려 있는 동안 수집/분석을 진행하고, 탭을 닫았을 때는 재접속 후 계속할 수 있다.
