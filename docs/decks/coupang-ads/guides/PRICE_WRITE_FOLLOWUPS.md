## 구조적 한계 (기록용, 고칠 대상 아님)

- **PUT 도달 후 응답 유실·해석 실패** — 2026-10-09 부터 쓰기 전 가격 ≠ 목표가인 경우 재조회로 성공을 확정하므로 대부분 바로잡힌다. 남는 경우: 쓰기 전 가격을 못 읽었거나 이미 목표가였을 때는 응답이 실패면 그대로 실패로 기록된다(안전한 쪽 오류).
- **최저가(`apMinSalePrice`) 는 확인할 수 없다** — 쿠팡에 조회 API 가 없다. 판매가 재조회 성공은 최저가 반영을 증명하지 않는다.
- **C2 검증은 생성 시점 1회뿐** — 워커는 `payload.targets[].vendorItemId` 로 실행하므로, 잡 생성~실행 사이(PENDING 은 최대 15분 뒤 만료)에 리스팅↔쿠팡옵션 매핑이 바뀌어도 재검증되지 않는다. 쿠팡에는 생성 시점 옵션에 쓰이고, 스냅샷 갱신은 `report` 가 vendorItemId 기준으로 하므로 실제로 쓴 옵션에 찍힌다.
- **`report` 라우트의 키 비교가 평문 `===`** — `resolveCollectionAuth` 경로로 바꾸면서 `timingSafeEqualString` 에서 벗어났다. 전체 길이 API 키에 대한 원격 타이밍 공격은 실효성이 없다고 판단.
- **워크스페이스 재해석으로 인한 stale** — `report` 가 보고 시점에 workspaceId 를 다시 해석하므로, 잡 실행 중 `InvStorageLocation` 연결이 바뀌면 `count=0` → `{stale:true}` 로 결과가 기록되지 않는다. reap cron 이 10분 뒤 재큐하고 3회째면 FAILED 로 끝난다(가격 PUT 은 멱등). 체인이 결정적이라 실위험은 거의 0.

## 이번 작업에서 드러난 레포 사실 (다음 사람용)

- **쿠팡 가격 변경 API 의 실제 성공 응답은 최상위 `code:"SUCCESS"`** 다(문서의 중첩 `data.code` 형태가 아님). 문서만 믿고 파서를 짜면 성공을 실패로 보고한다(2026-10-09 사고, PRD v1.1 §12.1). 응답 형태가 의심되면 실패 오류의 원문(`rawBody`)부터 볼 것.
- **쿠팡 현재가 직접 조회(진단용, 읽기 전용)** — 운영 워커 체크아웃(`/Users/kaleos/projects/workdeck-worker/worker`)에서 `getApiCredential()` + `buildApiClient()` + `fetchVendorItemStatus(client, vendorItemId)` 를 tsx 스크립트로 호출한다. 쿠팡 API 는 IP allowlist 라 워커 머신에서만 된다.
- **쿠팡 상품 API `statusName` 은 전부 "승인완료"** — 판매중지 여부를 알 수 없다. 매칭 화면은 상품명의 "판매중지" 문구로 추천만 한다.

- **`tsconfig.json` 이 `worker` 를 exclude 한다.** 루트 `npx tsc --noEmit` 은 워커 코드를 타입체크하지 않는다. 워커를 고쳤으면 `cd worker && npx tsc --noEmit` 을 따로 돌려야 한다. 현재 그쪽에 `analysis-poller.ts` 기존 에러 4건이 있다.
- **워커 테스트도 루트 Jest 로 돈다**(`jest.config.ts` 가 `worker/` 를 포함). 가격 쓰기 테스트 5개가 `node:test` 를 import 해 `npm test` 에서 "테스트 0개"로 실패하던 것을 Jest 전역으로 바꿨다(2026-10-05). `node:assert/strict` 는 그대로 쓴다.
- **`*.e2e.test.ts` 는 `DATABASE_URL` 이 셸에 없으면 조용히 전건 skip 된다**(`describe.skip`). "28건 skip" 을 통과로 오인하기 쉽다. `export $(grep -E '^DATABASE_URL=' .env.local | head -1 | xargs)` 후 실행할 것.
- **`prisma migrate dev` 는 이 레포에서 구조적으로 불가능하다.** shadow DB 에 Supabase 관리 `storage` 스키마가 없어 기존 마이그레이션 replay 가 실패한다. `migrate diff --from-schema <파일> --to-schema <파일> --script` + `migrate deploy` 가 정규 경로이고, **라이브 DB 기준 diff 는 절대 금지**(공유 dev DB 에 타 브랜치 객체가 올라가 있어 DROP 구문이 섞인다).
